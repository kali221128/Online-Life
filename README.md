<section class="chapter reveal" id="xu">
  <div class="ch-num">序</div>
  <h2 class="ch-title">为什么会有这个网页</h2>
  <p class="ch-lead">先自我介绍一下。我叫董易龙，江苏徐州人，现在是一名初二学生，也是一个写代码的人。这听起来有点矛盾，一个初中生，怎么就成"写代码的人"了？这正是我想在这个网页里说清楚的事。</p>
  <p>身边总有人问我，你一个学生，整天抱着电脑敲那些看不懂的英文，有什么用？作业写完了吗？我一开始不知道怎么回答，就笑笑说，觉得好玩。后来问的人多了，我自己也认真想过这个问题——到底为什么要写代码，为什么放着好好的周末不过，非要坐在屏幕前一坐就是一下午。</p>
  <p>答案其实很简单：因为好奇，因为喜欢，因为有些东西你一旦看见了，就再也放不下了。这个网页不是简历，也不是教程，更不是拿来炫耀什么。它只是我把自己这几年走过的路，一笔一笔写下来。写给我自己看，也写给那些和我一样，对着电脑屏幕有过同样好奇的人看。</p>
  <p>我想把这段经历记下来，还有一个私心。我这个人记性不算好，很多当时觉得刻骨铭心的瞬间，过了一两年再去想，细节就模糊了。我害怕再过几年，我会忘记第一次写出"你好，世界"时那个激动得手都在抖的下午。所以我把它写在这里，像在备忘录里存一个重要的文件——怕丢，就存个备份。</p>
  <div class="note reveal">
    <span class="tag">先说清楚</span>
    <p>这里面写的每一件事，都是真实发生过的。没有夸张，没有编造，也不往自己脸上贴金。我干过的蠢事、踩过的坑、气到摔键盘的时刻，我也都写出来了。因为我觉得，一个人走过的路，光鲜的部分和不光鲜的部分拼在一起，才是完整的。</p>
  </div>
  <p>大概从四年级算起，到今天，差不多四年的时间。四年听起来不长，可是对一个小学都还没毕业的孩子来说，这四年几乎占据了他对"世界"这个概念的全部认知。我的很多世界观，就是在这四年里，被一行一行代码慢慢塑造出来的。</p>
  <p>这篇手记会有点长，可能会花掉你一些时间。如果你愿意，泡杯水，慢慢看。看完之后你大概就能明白，一个普通的徐州小孩，是怎么从点开4399的小游戏，一路走到研究编译器原理的。</p>
  <p>我还想提前说一句：这篇手记里写的，都是我这个年纪、我这个人眼中的世界。我承认，我还有很多不懂的东西，很多看法可能还很幼稚，很多判断可能以后会被推翻。但这正是我想留下的"原样"——不是"成熟"的我写的总结，而是"现在"的我写的记录。等很多年后，我再回来看，我希望能看到的是"当年的董易龙"，而不是"美化过的董易龙"。</p>
  <p>还有一点，我也想坦白：我写这篇手记，其实也有点"私心"。我这个人，不太会说话，也不太会交朋友，跟人待在一起的时候，有时候不知道说什么好。但对着电脑，对着这堆文字，我却能滔滔不绝。所以，这篇手记，某种程度上，也是我"想说却没说出口的话"的寄存处。我把它们放在这里，如果有人能懂，那是我的幸运；如果没人看，那至少我自己，看得懂。</p>
  <p>好了，闲话不多说。故事，就从那台嗡嗡响的旧电脑开始吧。</p>
  <blockquote>
    别人问我为什么要写代码，我说不清。后来我想明白了——不是我在写代码，是代码一直在叫我。
    <span class="who">—— 董易龙，写于某天深夜</span>
  </blockquote>
</section>

<section class="chapter reveal" id="c1">
  <div class="ch-num">第一章</div>
  <h2 class="ch-title">四年级，那台旧电脑</h2>

  <p class="ch-lead">所有故事的起点，都是我家客厅角落里那台又老又卡的台式机。它开机要一分多钟，风扇转起来嗡嗡响，跟拖拉机似的。可对我来说，那台破电脑就是通往另一个世界的大门。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">一、周末的那一个小时</h3>
  <p>四年级之前，我对电脑的印象特别模糊。学校里有一间机房，一进去要穿鞋套，电脑屏幕上贴着蓝蓝的标签，写着"请勿随意关机"。那时候信息课教的都是开关机、用鼠标点图标、练打字。老师在上面讲，我就在底下偷偷点开画图，拿那个小铅笔头画小人。说实话，那会儿我压根不知道电脑除了画画和打字还能干什么。</p>
  <p>我家那台电脑是别人家淘汰下来给的，牌子都看不清了，显示器是老式的，屁股后面鼓出来一大块，像个小电视。家里当时也没装宽带，只有一张移动的流量卡，插在一个像U盘一样的东西里，叫"上网卡"。网速慢到什么程度呢？开一个网页，要先看那个小圈圈转上半天。我爸妈平时不让碰，只有周末写完作业，才允许我玩一个小时。</p>
  <p>就这一个小时，成了我整个星期最期待的事情。</p>
  <p>我玩的是4399。那会儿的4399简直是孩子的天堂，里面的游戏多到数不清。我玩的最多的是赛尔号、洛克王国、造梦西游，还有生死狙击。生死狙击是个网页射击游戏，要注册账号，我就拿个小本子，把账号密码一行一行记下来，本子封面上歪歪扭扭写着"重要机密，不许偷看"。其实那里面哪有什么机密，全是游戏账号。</p>
  <p>我记得特别清楚，赛尔号里有一只要攒很久才能抓到的精灵，我为了抓它，周六早上六点就爬起来，趁爸妈还没醒，偷偷把电脑打开，想着趁早上人少好抓一点。结果那天网络特别卡，加载了快十分钟才进游戏，我急得直跺脚，又不敢出声，怕被发现了没收电脑。现在想想，那真是又好笑又心酸。</p>
  <p>可是玩着玩着，我心里就冒出一个问题：这些游戏到底是怎么来的？为什么我点一下，它就能跑起来？为什么这个网页上有小人，别的网页上是字？屏幕背后到底是什么在干活？</p>
  <p>这个问题一冒出来，就再也压不下去了。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">二、想看看里面是什么</h3>
  <p>我开始干一件现在想起来特别"欠"的事——在网页上乱点右键。我发现在网页的空白处点右键，会弹出一个菜单，里面有一项叫"查看源代码"。我点开一看，好家伙，满屏的英文和尖括号，乱七八糟的，我一个字都看不懂。但我当时就觉得，这里面一定藏着什么秘密，那些小人和按钮，八成就是这些乱七八糟的东西变出来的。</p>
  <p>我还干过一件更傻的事。我在游戏里发现有个按钮，点它会跳转到另一个页面，我就一直盯着浏览器最底下那一条地址栏看，想看看它到底是怎么"跳"过去的。结果当然是什么也没看出来，只是记住了网址里那些字母。后来我才知道，那些看起来没规律的字母，叫作URL，是网页的地址，而这背后还有一套"协议"在指挥一切——当然，这是很久以后才弄明白的事了。</p>
  <p>那时候家里的大人没一个懂电脑。我问我爸，网页是怎么做出来的？我爸说，那是"高科技"，是程序员弄的。我又问，程序员是干什么的？我爸想了想，说，就是专门玩电脑的，把电脑玩明白了，就能让它干活。我听完这句话，心里咯噔一下——原来"玩电脑"还能玩到这种程度？</p>
  <p>从那天起，我就开始留意一切跟"做游戏""做网页"有关的东西。放学回家，我会趁写作业的间隙，在电脑上瞎搜。那时候的搜索引擎还不像现在这么聪明，我打字也慢，一个词一个词地敲，搜出来的东西七零八落的，但我看得津津有味。我现在都记得，我搜得最多的一句话是：<strong class="k">怎么自己做游戏</strong>。</p>
  <p>就是这一句话，把我领到了易语言的门口。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">三、第一次听说"易语言"</h3>
  <p>那天具体是星期几我忘了，只记得是个下午，阳光从窗帘缝里漏进来，正好打在电脑屏幕上。我照例打开搜索框，敲下"怎么自己做游戏"，回车。翻了几页，有一条结果的名字特别扎眼——它写着"易语言：中国人自己的编程语言"。后面还跟了一句类似"中文编程，零基础也能学会"的话。</p>
  <p>编程？语言？这俩词我当时一个都不懂。但"中文"两个字我认识，而且我看到"中国人自己的"这几个字，心里就没来由地涌起一股亲切感。你想想，一个四年级的小孩，看了一堆满屏英文的网页，突然看到有人说"中文也能编程"，那感觉就像在一片黑灯瞎火里，突然有人点了一盏灯。</p>
  <p>我点了进去。那是一个介绍易语言的页面，上面写着，易语言是一门以中文作为程序代码的编程语言，用汉字就能写出程序，让电脑听你的话。页面上还有几张截图，是软件的界面，上面密密麻麻全是中文——"程序""子程序""如果""循环""按钮""标签"。虽然我看不懂每一行是干什么的，但我看得懂这些字。</p>
  <p>那一瞬间我脑子里只有一个念头：我想试试。</p>
  <p>可是下载这一步，就卡了我好几天。</p>
  <p>首先是网速。那时候下载一个几十兆的安装包，要好长时间，进度条走得比蜗牛还慢，我还不敢挂在电脑上让它慢慢下，因为爸妈会看到。我只能趁家里没人的时候偷偷下，下一会儿，关掉，下次再接着下。就这样断断续续下了两三天，才终于把它下完。</p>
  <p>然后是杀毒软件。我清楚地记得，安装的时候，电脑上那个杀毒软件弹出来一个红色的警告框，说检测到"易语言"有风险，问我是否继续。我当时吓了一大跳，手都悬在鼠标上不敢点。我想了想，又去网上搜"易语言是病毒吗"，看到有人说，因为易语言写的程序常被一些人用来做外挂和破解工具，所以杀毒软件容易误报，软件本身是没问题的。我半信半疑，最后还是点了"允许"。</p>
  <p>后来的事情证明，这个选择是对的。如果那天我因为一个红色的警告框就退缩了，可能就没有后面这四年，也没有这个网页了。</p>
  <p>安装完成的那一刻，桌面上多了一个图标。我记得很清楚，那个图标是一个绿色的、圆圆的图案，像是某种印章。我双击它，屏幕一黑，接着弹出一个窗口——一个我从来没见过的主界面，左边是一排一排的组件，右边是属性面板，中间是一块白色的设计区。</p>
  <p>我的心脏跳得很快。我盯着那个界面看了好久，甚至不敢乱点，怕把它点坏了。那是我第一次真正意义上的"进入"一个编程工具，虽然当时我连"工具"这个词都说不出来。我只知道，这个东西，好像能让我做点什么。</p>
  <div class="note reveal">
    <span class="tag">写在这里</span>
    <p>四年级那会儿我根本不知道什么叫编程，也不知道什么叫语言。但我做对了一件事：当我看到一个东西让我好奇的时候，我没有看看就划走，而是真的去下载、去打开、去试了。好奇心这个东西，说起来不值钱，可要是没有那一下"点开看看"，后面的一切都不会发生。</p>
  </div>
  <p>后来的故事，就是从这个界面开始的。</p>

</section>
<!-- ===================== 第二章 ===================== -->
<section class="chapter reveal" id="c2">
  <div class="ch-num">第二章</div>
  <h2 class="ch-title">易语言：我写下的第一行代码</h2>

  <p class="ch-lead">易语言这个软件，现在知道的人可能不多了。但在那几年，它确实圆了很多中国孩子"用汉字写程序"的梦。而我，就是其中一个。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">一、用中文写代码</h3>
  <p>我永远不会忘记第一次真正看懂易语言界面时的那种感觉。它不像我以前在网页源代码里看到的那堆英文，它全是中文——"新建""打开""保存""程序""子程序""如果""循环"。你甚至不需要懂英语，光看字面意思，就能猜到它大概是要干嘛。</p>
  <p>易语言最吸引我的地方，是它那种"搭积木"式的开发方式。你要做一个窗口程序，不用从零开始敲代码去创建窗口，而是直接在中间那块白色的设计区上，从左边把组件拖过来就行。左边那排东西叫"组件箱"，里面有窗口、按钮、标签、编辑框、选择框、时钟、进度条……一大串名字。我一开始不知道哪个是干嘛的，就一个个往设计区上拖，拖上去又删掉，纯粹当玩具在玩。</p>
  <p>第一次成功写出程序，是在一个周六的下午。那天我照着网上一个很简单的教程，做了这么一件事：</p>
  <div class="code-wrap">
    <div class="code-head"><span class="dot r"></span><span class="dot y"></span><span class="dot g"></span><span class="lang">易语言 · 我的第一个程序</span></div>
<pre><code>.版本 2
.程序集 窗口程序集_启动窗口

.子程序 _按钮1_被单击
    信息框 (“你好，世界！”，0，，)</code></pre>
  </div>
  <p>过程是这样的：我先在窗口上拖了一个按钮，然后双击这个按钮，它就自动跳到了一个代码编辑区，光标停在"按钮1被单击"这一行里面。我在那行下面照着教程敲了那句"信息框（"你好，世界！"，0，，）"。敲完我还没太明白这行字是什么意思，教程说要先"编译"，我就点了工具栏上的"编译"按钮。</p>
  <p>然后，神奇的事情发生了——软件底下显示"编译成功"，在同一个文件夹里，多了一个后缀是 .exe 的文件，图标还是易语言的绿色小图标。教程说，这个文件就是"程序"，可以发给别人，别人双击就能运行。</p>
  <p>我那时候手都在抖。我双击那个 exe 文件，屏幕中央"啪"地弹出一个窗口，上面明明白白写着五个字：<strong class="k">你好，世界！</strong></p>
  <p>就这五个字，我看傻了。我盯着那个弹窗看了好久，又把鼠标放在"确定"按钮上，舍不得点，就怕点下去它就没了。那是我人生中第一次，让一台电脑完全按照我写的指令去做了一件事。虽然只是弹出一个字框，但那个下午，我觉得自己无所不能。</p>
  <p>那天晚上睡觉，我脑子里全是那个弹窗。第二天上学，我还在想它。我甚至想跟同桌炫耀，但又忍住了，因为我知道，那个程序其实是照着教程抄的，里面的门道我根本不懂。可即便如此，那种"我也能让电脑听话"的感觉，已经牢牢扎根在我心里了。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">二、一个个组件摸过来</h3>
  <p>从那以后，我的周末就被易语言彻底占领了。我把那一个小时的游戏时间，慢慢全换成了写程序的时间。我甚至觉得，写程序比玩游戏还好玩——因为游戏是别人设计好的，而程序是我自己设计的。</p>
  <p>我开始一个一个地研究组件。先是最常用的几个：</p>
  <p>标签（标签），就是窗口上一行静态的文字，用来显示信息的。编辑框，是可以输入文字的小方框。按钮就不用说了，点它会触发事件。选择框是个小方框，能打勾。组合框是个下拉列表。时钟最神奇，它能在设定的时间间隔里反复触发事件，就像一个隐形的秒表。</p>
  <p>我把这些组件轮着往窗口上放，再轮着双击它们写代码。那会儿我写代码基本靠猜，猜错了就报错，报错了就看错误信息。易语言报错还算客气，会告诉你错在第几行，只是它报错用的是它自己的术语，我一开始也看不懂，只能把错误信息复制到网上搜。</p>
  <p>后来我慢慢发现，组件和代码之间其实是有一套规律的：你拖一个按钮上去，双击它，写的就是"这个按钮被点了之后，要干什么"。你要让标签显示文字，就写"标签1.标题 = 内容"。要让编辑框内容变成标签的文字，就写"标签1.标题 = 编辑框1.内容"。这些"点"就像是把两个东西连在一起的线，学会连线，程序就活起来了。</p>
  <p>我写的第一个有点样子的程序，是一个计算器。当然，是特别简陋的那种：一个编辑框输入第一个数，一个编辑框输入第二个数，然后一个按钮负责加，一个按钮负责减，一个按钮负责乘，一个按钮负责除，最后用一个标签把结果显示出来。代码不长，但调了好几次才把"把文本转成数字"这一步搞对——原来从编辑框里读出来的是"文本"（一串字符），要先用一个命令把它转成"整数"才能做加减乘除。</p>
  <div class="code-wrap">
    <div class="code-head"><span class="dot r"></span><span class="dot y"></span><span class="dot g"></span><span class="lang">易语言 · 计算器的一角</span></div>
<pre><code>.子程序 _按钮_相加_被单击
    局部变量 数一， 整数型
    局部变量 数二， 整数型
    数一 ＝ 到整数 (编辑框1.内容)
    数二 ＝ 到整数 (编辑框2.内容)
    标签_结果.标题 ＝ 到文本 (数一 ＋ 数二)</code></pre>
  </div>
  <p>这个计算器做完，我得意了好一阵子，还专门把它编译出来，发给了一个同样爱玩电脑的同学。那同学回了我一句：你这东西有什么用？我仔细想了想，还真没什么用，手机自带的计算器比我这个好用一百倍。但我心里就是高兴，因为那是我自己写出来的。</p>
  <p>那个同学的反应，其实后来我遇到很多次。很多人都会问：你写的这东西有什么用？一开始我会有点泄气，会觉得他们说得对，自己写的确实是垃圾。但后来我想通了——<em class="k">有用没用是以后的事，先学会做出来，才是现在的事</em>。谁学走路的时候不是走得歪歪扭扭的？你先得能站起来，才能谈跑不跑得起来。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">三、网页背后的秘密</h3>
  <p>易语言玩熟了以后，我开始接触一个更让我着迷的东西——网页填表。这个词听起来挺专业，其实说白了就是：让程序自动去操作网页，比如自动输入账号密码、自动点按钮、自动翻页。</p>
  <p>我是怎么发现这个功能的呢？还是因为懒。我有个游戏账号，每次登录都要输账号密码，输多了就烦。我就在想，能不能写个程序，点一下，它自己就把账号密码填进去，再点一下登录？我一搜，发现易语言里还真有人干这个，而且有一个特别厉害的东西，叫"精易模块"。它把很多网页操作的命令都封装好了，不用自己一点点写。</p>
  <p>模块这个词，我也是那时候才第一次听说。它就像是一个装满了现成工具的大工具箱，你把它"引用"进来，就能直接用里面的命令。我第一次用精易模块成功让程序自动打开网页、填上账号密码、点登录的时候，那种成就感，比做计算器强了不知道多少倍。因为这次，程序是在"替我做事情"，它像一个会自己动的小人。</p>
  <p>可问题也来了。网页填表用着用着，我就遇到了很多搞不定的情况：有些按钮点了没反应，有些网页上的内容读不出来，有些登录框怎么都填不进去。我去网上查，才慢慢拼凑出一个真相——网页背后其实是一套"对话"。你访问一个网页，其实是你的电脑给服务器发了一个"请求"，服务器再给你返回一堆"数据"，你的浏览器把数据画成你看到的页面。</p>
  <p>那些能填表的工具，本质上是模拟你在跟服务器说话。但有些网页的"规矩"不一样，你得按它的方式来，不然它不理你。为了搞懂这些，我开始接触到两个词：<strong class="k">GET</strong> 和 <strong class="k">POST</strong>。GET 就像是你去问人家要东西，POST 就像是你要把东西交给人家。还有请求头、Cookie、会话……一串一串的新名词砸过来，我一个四年级刚毕业的小孩，看得头晕眼花，但又忍不住一直看下去。</p>
  <p>那段时间我还用了一个叫"抓包"的办法——就是把电脑和服务器之间传递的数据偷偷截下来看。有一回，我截到一串特别长的数据，里面密密麻麻全是字段，我对着它研究了半天，最后发现其中一个字段就是我要找的"登录状态"。那一刻我忽然明白了：原来那些看起来高深莫测的网页，底层就是这些看得见摸得着的数据在跑来跑去。你只要懂了它们是怎么跑的，你就能让它们按你的意思跑。</p>
  <blockquote>
    我第一次觉得，电脑不神秘了。它不是魔法，它是规则。而规则，是可以被学会的。
    <span class="who">—— 学网页填表时的一点点觉悟</span>
  </blockquote>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">四、中文编程的甜和苦</h3>
  <p>用易语言的那两年，我对它的感情很复杂。一方面，它是我的启蒙老师，没有它，我可能到现在都不知道编程是什么；另一方面，我也越来越清楚地看到它的局限。</p>
  <p>先说说它的甜。中文编程最大的好处，就是没有门槛。一个四年级的小孩，不用先背几百个英文单词，不用搞懂什么叫"function"什么叫"class"，你只要会看中文，就能开始写程序。而且易语言的界面设计得很"亲民"，拖拖拽拽就能做出窗口，特别适合用来建立信心。对我来说，它让我在最容易放弃的年纪，坚持了下来。</p>
  <p>再说说它的苦。第一，资料少。网上关于易语言的教程，翻来覆去就那么几样，而且很多都很老，报错信息搜不到答案的时候，只能自己瞎琢磨。第二，生态窄。它不像主流语言那样，有全世界的人在贡献代码和工具，很多功能你要自己造轮子。第三，也是最让我难受的一点——用易语言写的程序，很容易被杀毒软件误报。我辛辛苦苦写一个东西，一编译，杀毒软件就跳出来说"检测到风险"，我明明什么都没干坏啊。后来我才明白，这是因为它生成的程序特征比较特殊，被一些别有用心的人用去做外挂和破解工具，连累了好人。</p>
  <p>还有一件事，让我开始认真地怀疑"中文编程"这条路。有一天，我在网上看到一句话，大意是：编程语言里的英文单词，其实不是"英语"，而是一套规则的名字，你换成中文，规则还是那套规则，只是换了件衣服。我当时不太服气，但后来我慢慢想明白了——<em class="k">语言是外壳，逻辑才是内核</em>。你用中文写的"如果"，和用英文写的"if"，背后干的其实是同一件事：判断一个条件成不成立。</p>
  <p>但想明白归想明白，我心里那个念头不但没消失，反而更强了。我那时候隐隐约约有一个想法：既然语言只是外壳，那我是不是也能做一套自己的外壳？让更多看不懂英文的人，也能写程序？这个想法当时只是一个模糊的影子，我甚至没敢跟任何人说，但它一直藏在我心里，直到很多年后，它变成了一个真正的项目——当然，这是后面的事了。</p>
  <div class="note reveal">
    <span class="tag">这段路的收获</span>
    <p>易语言教会我的，不只是怎么拖组件、怎么填表，更重要的是三件事：第一，程序是人写的，不是天上掉下来的，谁都能学；第二，报错不可怕，可怕的是报错了不去查；第三，中文能编程，这件事本身给了我一个信念——门槛是可以被打破的。</p>
  </div>
  <p>后来，我在易语言里能写的东西越来越复杂，可我也越来越觉得，它有些"罩不住"我了。我想要的，是那种能接触更深层的东西。也就是在那时候，一个叫 Python 的词，开始频繁地出现在我眼前。</p>

  <h2 class="ch-title">Python：换一种活法</h2>

  <p class="ch-lead">如果说易语言是我编程路上的第一个家，那 Python 就是让我第一次看到"外面的世界有多大"的那扇窗。它像一把万能的瑞士军刀，什么东西都能干一点，而且上手快得惊人。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">一、听说有个叫 Python 的东西</h3>
  <p>我是怎么知道 Python 的？说起来有点好笑。那阵子我在易语言的论坛里混，经常看到有人发帖子说"易语言是不是要凉了""现在学编程都学 Python"。还有个帖子更直接，说"Python 是世界上最简单的编程语言，小学生都能学会"。我当时就有点不服气——还能比我用的易语言简单？</p>
  <p>但我嘴上不服，心里还是记下了这个名字。后来我又看到一篇文章，说很多大公司都在用 Python，什么人工智能、爬虫、数据分析，都用它。这下我更坐不住了。我那时候的想法很简单：<em class="k">一个东西，既简单又能干大事，那我不学它学谁？</em></p>
  <p>下载安装的过程，比易语言顺利多了。我从官网下载了安装包，双击安装。安装的时候有个特别贴心的选项，叫"Add Python to PATH"，翻译过来大概就是"把 Python 加到系统环境变量里"。我当时完全不懂这是干嘛的，但网上教程说一定要勾上，我就勾了。就是这个小小的勾，让我后来少走了很多弯路——因为如果你不勾，你在命令行里敲"python"它就找不到，你装了个寂寞。</p>
  <p>装完之后，我打开命令行（就是那个黑底白字的窗口），学着教程敲了第一个命令：</p>
  <div class="code-wrap">
    <div class="code-head"><span class="dot r"></span><span class="dot y"></span><span class="dot g"></span><span class="lang">Python · 第一行</span></div>

  <p>看到那行"你好，世界"被原封不动地打印出来，我心里其实挺平静的。因为在易语言里，我已经见过比这更花哨的弹窗了。但平静归平静，我还是隐约感觉到，这次有点不一样——因为它不是弹窗，不是图形界面，而是最纯粹的、一行代码换来一行输出的过程。它干净、直接，像跟电脑面对面说了一句话。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">二、从爬虫开始认识它</h3>
  <p>学 Python，我走了一条和大多数人不太一样的路——我几乎没有系统地学过语法，而是直接上手"干活"，缺什么查什么。这个方法在 Python 这里意外地好用，因为 Python 的语法真的太接近自然语言了。你看这段代码：</p>
  <div class="code-wrap">
    <div class="code-head"><span class="dot r"></span><span class="dot y"></span><span class="dot g"></span><span class="lang">Python · 往列表里加东西</span></div>
<pre><code>names = []
for i in range(5):
    names.append("名字" + str(i))
print(names)</code></pre>
  </div>
  <p>你看，"for i in range(5)"，翻译成人话就是"让 i 从 0 到 4 挨个来一遍"；"names.append"就是"往列表里加一个东西"。几乎不需要翻译，扫一眼就知道它在干嘛。这种"能看懂"的感觉，给了我极大的信心，让我敢直接跳到真正想做的事情上——爬虫。</p>
  <p>前面我说过，我在易语言里已经玩过网页填表、抓包。到了 Python，我发现同样的活，Python 干起来简直像开挂。两个库，一个叫 requests，负责发请求；一个叫 BeautifulSoup，负责解析网页。加起来不到十行代码，就能把一个网页上的内容全都抓下来。</p>
  <div class="code-wrap">
    <div class="code-head"><span class="dot r"></span><span class="dot y"></span><span class="dot g"></span><span class="lang">Python · 第一次爬网页</span></div>
<pre><code>import requests
from bs4 import BeautifulSoup

resp = requests.get("https://example.com")
soup = BeautifulSoup(resp.text, "html.parser")
for title in soup.find_all("h2"):
    print(title.get_text())</code></pre>
  </div>
  <p>我第一次跑通这个，是在一个周日的傍晚。窗外天都黑了，我盯着屏幕上哗啦啦打印出来的标题列表，整个人都愣住了。那些标题，就是那个网页上所有的二级标题，一个不多一个不少。那一刻我忽然意识到，我手里这个东西，已经不再是"玩具"了——它是真的能自动从网上海量信息里，把我要的东西捞出来的工具。</p>
  <p>然后我就开始到处爬。爬小说，把整本小说一章一章抓下来存成文本文件，存了厚厚一沓，其实我也没怎么看。爬图片，把图库里的图按页全抓下来，塞进一个文件夹，塞了好几个 G，其实我也没怎么翻。我就像个刚得到新玩具的孩子，什么都要试一试，也不管有没有用。但正是这些"没用的尝试"，让我把 requests、BeautifulSoup、循环、条件判断这些语法，练得滚瓜烂熟。</p>
  <p>爬着爬着，我就撞墙了。有些网站，我请求一次还好，请求多了，它就开始拒绝我，返回一堆我看不懂的错误码。我一开始以为是自己的代码写错了，翻来覆去检查半天，后来才在网上查到——那叫<strong class="k">反爬虫</strong>。网站知道有人（或程序）在批量抓它的数据，就设了各种关卡，比如检测你是不是真人、是不是同一个 IP 请求太频繁，等等。</p>
  <p>为了"过五关斩六将"，我开始研究请求头、Cookie、代理 IP、延时。我发现，原来我之前在易语言里隐隐约约摸到的那套"对话"规则，在 Python 里被放大得清清楚楚。每一个网站，都有一套它自己的脾气，你得顺着它的脾气来，它才理你。那段时间，我像在玩一个大型的解谜游戏，被卡住了就查，查到了就继续，乐此不疲。</p>
  <div class="note reveal">
    <span class="tag">一个朴素的领悟</span>
    <p>爬虫这东西，很多人一听就想到"黑客"、想到"攻击"。但我后来慢慢明白，爬虫的本质不是破坏，而是"读懂"——读懂一个网站是怎么组织数据的，读懂网络是怎么流转的。它是我理解互联网的第一块基石。至于能不能乱爬，那是另一码事，规矩是要守的。</p>
  </div>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">三、Python 能干的杂活越来越多</h3>
  <p>爬虫玩腻了，我开始发现 Python 的"百宝箱"属性——它几乎什么都能干。我陆陆续续试了好多方向，每一个都让我觉得"哇，还能这样"。</p>
  <p>先是用 pygame 写游戏。我照着教程写了一个贪吃蛇，后来又自己瞎改，把蛇的颜色、速度、加分规则全改了一遍，改得乱七八糟，但跑起来特别带劲。我还试着写飞机大战，画面上那个小飞机是我用像素点一点一点拼出来的，丑得没法看，但我还是玩得津津有味。写游戏让我明白了一件事：游戏的核心不是画面，是<em class="k">规则</em>——你定了什么规则，游戏就是什么样子。</p>
  <p>然后是用 tkinter 写界面。tkinter 是 Python 自带的一个图形界面库，做出来的窗口虽然没有易语言那么"拖拽即所得"，但也够用了。我拿它做了各种小工具，比如一个批量改文件名的，一个定时提醒自己起来喝水的，还有一个简易的记账本。虽然这些工具都很粗糙，但每做完一个，我都能实打实地感觉到：程序是真的能帮人省事的。</p>
  <p>再后来，我接触到了一个对我来说意义很大的东西——win32api。它是 Python 用来调用 Windows 系统功能的接口。你听这名字就知道，它离"系统"很近。我用它干过几件事：让程序模拟鼠标点击、模拟键盘按键、读写注册表、获取系统信息。有一回，我写了一个程序，能每隔几分钟自动帮我按一下键盘上的某个键，这样电脑就不会休眠了。虽然这功能没什么技术含量，但那个程序跑起来的时候，我看着屏幕，第一次觉得：原来我不是只能写"网页上跑的东西"，我还能碰到电脑更深的地方。</p>
  <p>那段时间，我对 Windows 系统本身也产生了浓厚的兴趣。我开始研究任务管理器里那些进程都是什么，研究注册表里那些乱七八糟的键值是什么，研究为什么程序能开机自启，为什么有的软件装在 C 盘就慢、装在 D 盘就快。我像一只发现了新大陆的蚂蚁，在 Windows 这个庞大的系统里东摸摸西碰碰，每搞懂一个名词，就像点亮地图上的一块区域。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">四、Python 的甜与苦</h3>
  <p>用了一段时间 Python 之后，我慢慢摸清了它的脾气。它的甜，甜在"快"和"省"——写代码快，几乎不用管内存、指针那些麻烦事；生态好，你想到的绝大多数功能，都有人帮你封装好了，装个库就能用。它的苦，苦在"慢"和"大"——它跑起来确实比 C++ 那种编译型语言慢，特别是干重活的时候；而且打包成 exe 特别臃肿，一个简单的程序打包出来，动辄几十兆，还是个假 exe，运行前要先解压。</p>
  <p>但最让我在意的，是另一种"隔"的感觉。用 Python 写东西的时候，我总觉得它隔着一层纱——我能指挥它，但我看不到它底层到底在干什么。那些库，一个个都是黑箱子，我调用它们，它们替我办事，但我不知道它们内部是怎么运转的。这种感觉，对于一个好奇心特别重的人来说，简直是一种折磨。</p>
  <p>我开始频繁地思考一个问题：这些东西，究竟是怎么跑起来的？我写的那行"print"，是怎么变成屏幕上那行字的？我点的那个按钮，是怎么触发那串动作的？Python 说它自己能解释，那解释器又是什么？解释器又是谁写的？</p>
  <p>这一串问题，像连环炮一样，一个接一个地冒出来。我知道，光靠 Python，我是永远回答不了这些问题的。我得往更下面走。而在编程的世界里，"更下面"意味着什么，答案几乎只有一个——<strong class="k">C 语言，以及它的亲戚 C++</strong>。</p>
  <blockquote>
    有人往上看，想做出更漂亮的东西；有人往下看，想弄懂东西是怎么做的。我大概是后一种人。
    <span class="who">—— 决定学 C++ 之前的想法</span>
  </blockquote>

  <h2 class="ch-title">C/C++：往下走，再往下走</h2>

  <p class="ch-lead">学 C++ 之前，我做了很多心理准备。我知道它难，但我没想到它这么难——第一次见到"指针"这个词的时候，我盯着它看了十分钟，脑子里一片空白。可也正是这段"痛苦"的经历，把我真正拽进了编程的深水区。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">一、第一次见到 printf</h3>
  <p>我学 C++ 的第一个工具是 Dev-C++，一个看起来特别"复古"的软件，界面灰扑扑的，工具栏上的图标画质还停留在上个世纪。但它免费、小巧、开箱即用，特别适合当时的我。我在里面建了一个新项目，照着教程敲下了人生第一段 C++ 代码：</p>
  <div class="code-wrap">
    <div class="code-head"><span class="dot r"></span><span class="dot y"></span><span class="dot g"></span><span class="lang">C++ · 第一段</span></div>
<pre><code>#include &lt;stdio.h&gt;

int main(void)
{
    printf("你好，世界！\n");
    return 0;
}</code></pre>
  </div>
  <p>然后我点了一下那个绿色的"编译并运行"按钮。屏幕一闪，一个黑框框弹出来，上面印着一行"你好，世界！"，然后"啪"地一声，黑框框就消失了。我还没看清呢，它就没了。</p>
  <p>我一开始以为程序出错了，怎么一下就没了？后来才知道，那是因为程序运行得太快，跑完就自己关掉了。要想让它停住，得在最后加一句"getchar()"或者"system("pause")"，让它等着你按一下键盘。就这么一个小问题，当时的我琢磨了半天，最后在别人的程序里看到了"system("pause")"这行字，才算弄明白。</p>
  <p>这件事给我留下了很深的印象，因为它让我第一次真切地体会到：C/C++ 和 Python 不一样。Python 像是一个温和的保姆，什么都帮你想到；而 C/C++ 像是一个只认死理的工头，你不说停，它就一溜烟跑完了，你怪它跑太快，它还觉得是你不懂规矩。你得学会跟它"约法三章"。</p>
  <p>接下来就是漫长的受虐时光。变量、数据类型、循环、函数，这些在 Python 里我早就用过的东西，到了 C++ 里全都变了味。Python 里你写"a = 1"就行了，C++ 里你得先"int a;"告诉它这是个整数，然后才能"a = 1"。Python 里你不用管内存，C++ 里你得自己申请、自己释放，忘了释放就会"内存泄漏"。还有那个让我眼前一黑的"指针"——一个变量，存的是另一个变量的地址。地址？地址是什么？我指着电脑屏幕问，是这个的地址吗？</p>
  <p>那段日子，我几乎每天都在崩溃和重建之间反复横跳。有时候一个报错，我怎么也找不到原因，气得想摔鼠标；有时候一个困扰好久的问题突然通了，那种豁然开朗的感觉又让我觉得，前面受的苦全值了。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">二、指针与内存：第一次"看见"电脑的脑子</h3>
  <p>要说 C++ 里最难啃的骨头，非指针莫属。很多人就是死在指针这一关，然后转头回去学 Java、学 Python。我也差点被劝退，但后来我用一个笨办法把它弄明白了——我把它想象成一个"快递单"。</p>
  <p>你想啊，你的电脑内存就像一个大仓库，里面有一排一排的格子，每个格子都有一个编号。你声明一个变量，就是在仓库里占了一个格子，往里面放东西。而"指针"是什么呢？它是一张快递单，单子上写的不是东西本身，而是"东西放在哪个格子（编号）"。</p>
  <p>为什么要有指针？因为有时候，你不想把东西整个搬来搬去（那样又慢又占地方），你只想告诉别人"东西在那个格子里，你自己去看"。特别是当你处理一大堆数据的时候，直接用指针指过去，比把数据复制一遍高效太多了。这就像你有一整柜子书，与其一本本搬给别人看，不如直接把柜子的位置告诉他。</p>
  <p>想通这一点之后，指针在我眼里就没那么吓人了。我甚至开始觉得它很优雅——用一个很小的东西，去"指"一个很大的东西，四两拨千斤。后来我还了解到，为什么 C/C++ 写的程序又快又省内存，很大一部分功劳就在这——它让程序员能直接跟内存打交道，想怎么用就怎么用。当然，这也意味着，用错了会很惨。你指错了格子，程序就会崩，甚至悄悄读错数据，这种"悬空指针""野指针"的坑，我踩了不知道多少个。</p>
  <div class="code-wrap">
    <div class="code-head"><span class="dot r"></span><span class="dot y"></span><span class="dot g"></span><span class="lang">C++ · 指针初体验</span></div>
<pre><code>int a = 10;      <span class="c-cmt">// 一个格子，里面放着 10</span>
int *p = &amp;a;     <span class="c-cmt">// p 记下了 a 的格子编号</span>
*p = 20;         <span class="c-cmt">// 顺着编号找过去，把里面的 10 改成 20</span>
printf("%d", a); <span class="c-cmt">// 输出：20</span></code></pre>
  </div>
  <p>说实话，我到现在也不敢说自己把指针玩明白了，但它让我第一次摸到了"内存"的边。以前我用 Python 的时候，内存这个东西对我是完全隐形的，我压根不知道它存在。到了 C++，它终于从幕后走到了台前。我越来越觉得，编程这事儿，就像剥洋葱，你每往下一层，就会看到一个更大的世界。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">三、Windows 底下的那些事</h3>
  <p>C++ 玩熟了基础语法之后，我的兴趣又回到了 Windows 系统上——而且这次，我不满足于像 Python 那样"隔着纱"操作了。我要直接用 C++ 去调 Windows 的接口，去碰那些真正贴近系统的东西。</p>
  <p>这里要引入一个词，叫 <strong class="k">Windows API</strong>。API 的全称是 Application Programming Interface，翻译过来就是"应用程序编程接口"。你可以把它理解成 Windows 系统对外开的一扇扇门——你想让系统帮你干点什么，就去敲对应的门。比如你想创建一个窗口，就调用 CreateWindow；你想画点什么，就调用 GDI 相关的函数；你想让程序等一会儿，就调用 Sleep。</p>
  <p>我第一次用 C++ 创建出一个属于自己的窗口时，那种感觉和用易语言拖一个窗口出来完全不一样。易语言是"给你一个现成的窗口，你往里摆东西"；C++ 是"你亲手告诉系统，我要一个窗口，它多大、什么样式、标题写什么"，然后看着系统真的给你造出来一个。前者像是在别人家的房子里摆家具，后者像是在空地上亲手盖房子。虽然我盖的那"房子"丑得不行，就一个灰底白框，但它是我一砖一瓦砌起来的。</p>
  <p>我还记得我第一次接触到"消息循环"这个概念时的震撼。Windows 是一个"事件驱动"的系统——它时时刻刻在收集"消息"，你点了一下鼠标，就有一条"鼠标被按下了"的消息产生；你敲了一下键盘，就有一条"键被按下了"的消息产生。你的程序要做的，就是不停地"听"这些消息，听到跟自己有关的，就做出反应。这个机制叫"消息循环"。我当时觉得这设计妙极了——原来我们用的每一个程序，骨子里都是一个"不停听消息、不停回消息"的哨兵。</p>
  <p>那段时间，我特别痴迷于研究 Windows 系统本身。我去看了任务管理器里的进程，去看注册表，去看系统目录里那些 DLL 文件。我甚至试着用 C++ 写过一个简单的"进程管理器"，能列出当前所有在跑的进程、显示它们占了多少内存。虽然功能简陋，但每看到一个进程被我"揪"出来，我都觉得，自己离这台电脑的心脏又近了一步。</p>
  <div class="note reveal">
    <span class="tag">关于工具的选择</span>
    <p>在我开始想做图形界面工具的时候，有人跟我说，用 Qt 吧，拖拖拽拽就能做界面，跨平台还好用。我研究了一圈，最后还是放弃了。原因有两个：一是 Qt 的授权协议对我来说有法律风险，我搞不太清楚，也不想给自己留隐患；二是我越来越喜欢"手写界面"的那种掌控感。我宁愿自己用 Windows API 一行一行把控件画出来，也不要那种黑箱。后来我甚至给自己定了个标准——能用纯 C++ 手写的，就不用框架。</p>
  </div>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">四、让两台电脑说话</h3>
  <p>C++ 带给我的又一个惊喜，是网络编程。我第一次用 socket（套接字）写出一个能让两台电脑互相通信的程序时，激动得差点从椅子上跳起来。</p>
  <p>什么是 socket？你可以把它想象成两台电脑之间的"电话线"。一方要"拨号"（去连接别人），一方要"接听"（等别人来连）。连上了，两边就能互相传数据。听起来很简单，但真正写起来，里面的细节多到让人抓狂——要指定 IP 地址、端口号、协议类型，要处理连接失败、断开重连，要管理数据收发……我第一次写完一个"客户端连服务器，发一句话，服务器回一句话"的小程序时，测试用的还是自己连自己，本地回环，就这么个"自己跟自己打电话"的玩意儿，我调试了一个晚上。</p>
  <p>但当我真的把它跑起来，看到两台电脑（一台是家里的，一台是同学家的）真的能传消息的时候，那种感觉简直无法形容。我那时候深刻地体会到了一件事：<em class="k">网络不是抽象的，它是实打实的字节，在一根根看不见的"线"里跑来跑去</em>。</p>
  <p>后来我又研究了一个更复杂的东西——内网穿透。原因是这样的：我写的那个聊天程序，只有两台电脑在同一个局域网里才能连上。可我想让它们"隔着整个互联网"也能连，那问题就来了。因为大多数家庭电脑都没有公网 IP，它们在路由器后面，外面的人根本找不到它们，这就叫"内网"。</p>
  <p>那怎么办？答案就是"内网穿透"。原理说复杂也复杂，说简单也简单——你可以找一台有公网 IP 的服务器当"中间人"，你的程序主动去连这台服务器，别人也连这台服务器，然后由服务器把两边的数据互相转达。这样，就算两边都在内网，也能"曲线救国"，通过中间人把话说上。我那时候用了一些现成的穿透工具来试验，也尝试着自己理解它的原理，什么 NAT、打洞、转发，一个一个名词啃过去。虽然很多地方我现在也只是一知半解，但那种"一层一层揭开谜底"的感觉，让我彻底上了瘾。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">五、对编译器的好奇</h3>
  <p>C++ 学得越深，一个念头就越强烈：我写的这些代码，到底是怎么变成那个能运行的 exe 的？</p>
  <p>以前用易语言的时候，我点"编译"，它"啪"地给我一个 exe，我从来没想过中间发生了什么。到了 C++，我知道我写的是源代码，电脑直接运行不了，得先"编译"。可"编译"到底是干什么？它怎么就把人写的英文字母，变成了机器能懂的 0 和 1？</p>
  <p>我开始查资料。然后我了解到了"编译原理"这门学科的存在。原来，编译器的工作分为好几个阶段：先"词法分析"，把你写的代码拆成一个个单词；再"语法分析"，看这些单词组合起来符不符合语法规则；然后"语义分析"，检查逻辑对不对；再生成中间代码、做优化，最后生成机器码。每一步都像一条流水线，把我的源代码，一步步"加工"成电脑真正能执行的指令。</p>
  <p>我知道这个消息的时候，整个人都愣住了。因为在我的想象里，"编译"就是一个黑箱子，输入源代码，输出 exe。可实际上，黑箱子里是一整套精密的流水线作业。我忽然意识到，我用了这么多年的编译器，其实本身就是一个无比复杂的程序——而写这个程序的，也是人。</p>
  <p>这个念头，像一粒种子，在我心里越埋越深。我那时候还不知道，几年之后，这粒种子会长成一个真正的大项目——我自己动手，去研究、去实现一门语言的编译。那是我当时连想都不敢想的事情，但命运这东西，有时候就是这么奇妙，你种下一颗种子，总有一天，它会在你意想不到的地方发芽。</p>
  <blockquote>
    你学得越深，就会发现越多"原来如此"的时刻。而每一个"原来如此"，都会把你引向一个更大的"为什么"。
    <span class="who">—— 学到编译原理时的感受</span>
  </blockquote>

      <p>它的想法，其实来源于我身边很多人。我经常看到有人想做个自己的主页、做个活动宣传页，但一提到代码就犯怵。我就想，为什么不能有一个工具，让人像搭积木一样，把文字、图片、按钮拖到页面上，就能直接生成一个能用的网站呢？市面上其实有类似的东西，但我总觉得它们要么太贵，要么太死板，我想做一个更"自由"的。</p>
      <p>于是「缔造者」就这么开始了。第一步，我定下了它的核心能力：<strong class="k">一键拖拽</strong>，把组件拖到画布上，就能实时看到效果；<strong class="k">自定义代码注入</strong>，让懂代码的人可以直接改 HTML、CSS，甚至写自己的 JS；还有最重要的一点——<strong class="k">响应式</strong>，也就是做出来的网站，在手机上、平板上、电脑上都要好看，不能只在电脑上能看，一上手机就乱成一团。</p>
      <p>这个"响应式"，是我给自己挖的第一个大坑。做前端的人都知道，一个页面在不同的屏幕尺寸下要自己"变形"，是很考验功夫的。我用媒体查询（media query）和弹性布局（flex）一点一点调，为了一个按钮在不同屏幕下的间距，我能调上半天。但我又很享受这个过程，因为每当我看着自己做的页面，从电脑屏幕上缩小到手机屏幕上，依然整整齐齐的时候，那种满足感是实打实的。</p>
      <p>接下来是最让我较真的一件事——安全。我这个人，对"安全"两个字有执念。我做这个建站工具，就一定要保证：用户通过我的工具生成的网站，不能被轻易注入脚本，不能被 SQL 注入攻击。因为我见过太多网站，因为开发者偷懒，没做过滤，结果被人注入了一堆恶意代码，整个网站都废了。我不想我的用户重蹈覆辙。所以在「缔造者」里，凡是有用户输入的地方，我都做了转义和过滤；凡是要跟数据库打交道的地方，我都用了参数化的方式，杜绝拼接 SQL。这些安全措施，可能用户根本看不见，但我知道，它们在替用户挡子弹。</p>
      <p>做这个项目的过程中，我最大的收获不是技术，而是一种"产品感"。我开始学会想：做出来的东西，到底是谁在用？他会不会用？他遇到问题怎么办？以前我只想着"我能不能做出来"，现在我开始想"别人用起来舒不舒服"。这大概就是一个"玩家"到一个"创造者"的转变吧。</p>
      <div class="aside">这个项目到现在也没完全做完。它的功能越加越多，代码量越来越大，我越来越感觉到，一个人单打独斗做一个"平台级"的东西，有多吃力。但我会继续做下去，一点一点地填坑。</div>

      <p>第二个项目，是一步更"作死"的棋——我自己写一个代码编辑器，也就是大家常说的 IDE。IDE 就是"集成开发环境"的缩写，像 Visual Studio、VS Code 那些，都是 IDE。我为什么会想自己写一个？一方面，是觉得市面上的 IDE 都太"重"了，开一个要等半天；另一方面，是我心里一直有个念头：我想做一个支持"几乎所有语言"的编辑器，计划里甚至要支持 200 种以上。</p>
      <p>你可能觉得，支持 200 种语言，这不是天方夜谭吗？其实，关键不在于这 200 种语言本身的实现，而在于你要设计一套"通用"的机制，让每一种语言都能"插"进来。语法高亮、代码折叠、括号匹配、自动补全——这些功能，其实都是可以在"语言无关"的层面做的。你做一套框架，然后每种语言往里填自己那份"词典"和"规则"，就能一个接一个地支持下去。</p>
      <p>这个项目的技术栈，我毫不犹豫地选了 C++。因为我要让它跑得快，要让它轻量。而且，我坚持界面要用原生方式手写，不依赖那些重型的界面框架——这既是我的技术洁癖，也是我对"掌控感"的追求。我还打算内置一个 MinGW 编译器，这样用户在编辑器里写完 C/C++ 代码，不用另外装编译器，点一下就能编译运行，就像一个小型的"开箱即用"的开发环境。</p>
      <p>写编辑器核心的那段时间，是我这几年编程经历里最"烧脑"的一段。你要处理光标移动、选区、滚动、撤销重做……每一个功能，背后都是一堆状态的维护。特别是"撤销重做"，我一开始想得太简单，以为存个快照就行，结果一做大文件就卡得要死。后来我查资料才知道，专业的编辑器是用"操作栈"来实现的——你每做一步操作，就记录一个"反操作"，撤销的时候把反操作执行一遍。这样既快又省内存。当我终于把这个机制跑通的时候，那种"原来如此"的畅快感，比吃了十顿大餐都舒服。</p>
      <p>这个项目，同样远没有做完。支持 200 种语言，对我一个学生来说，注定是一条很长的路。但我不急，我把它当成一个长期的"作品"，慢慢打磨。我甚至想过，等它真的做出来了，我就要用它来写我自己的其他项目——用自己写的工具干活，那种感觉，光想想就很爽。</p>

      <p>这算是我把前面学的所有东西，串起来用的一次大实践。前端要画界面，我用的是手写的窗口；后端要传数据，我用的是 socket；两台电脑隔着互联网要能通信，我用的是前面研究过的内网穿透。当这三个东西第一次真正串起来，我在这台电脑上发消息，另一台电脑上真的弹出来的时候，我对着屏幕笑了好久。虽然那只是我自己搭的两个端在互发，但在我眼里，那就是整个世界。</p>
      <p>当然，作为一个对"安全"有执念的人，我怎么可能不加密。我在"信鸽"里做的加密方案，是我自认为最得意的一部分——我采用了<strong class="k">复合加密</strong>：用非对称加密（RSA）来保护一把随机生成的对称加密密钥（AES），再用这把密钥去加密真正要传输的消息。这么做的道理是：RSA 安全但慢，AES 快但需要双方共享密钥。那就让 RSA 去"护送"密钥，让 AES 去"干活"，各取所长。消息里的每一个 IV（初始向量）都是随机生成的，绝不重复使用。我还特别注意，程序运行完，内存里的密钥要及时清理掉，不能留下痕迹。这些细节，可能一般用户根本感知不到，但我知道，它们让"信鸽"更经得起考验。</p>
      <p>我一直觉得，安全不是一个功能，而是一种习惯。不是"加个密码就安全了"，而是每一个环节都要较真。这段话，是我这几年最深的体会之一。</p>
      <div class="aside">"信鸽"目前还是一个原型，离"真的能发给别人用"还有很长的路。但它证明了：一个学生，凭着自己一点点攒的知识，是能搭起一个完整的东西的。这对我来说，比什么都重要。</div>

      <p>"汉语言"的第一步，是设计它的"长相"。我想让它读起来像中文，但又不能失去编程语言的严谨。比如：</p>
      <div class="code-wrap">
        <div class="code-head"><span class="dot r"></span><span class="dot y"></span><span class="dot g"></span><span class="lang">汉语言 · 一个设想</span></div>
<pre><code>定义 函数 求和(数甲, 数乙)
    返回 数甲 + 数乙
结束

主程序()
    输出 求和(3, 5)
结束</code></pre>
      </div>
      <p>你看，"定义 函数""返回""主程序""输出"，全是中文。但它背后的逻辑，跟 C 语言一模一样——定义、传参、返回、调用。这也是"汉语言"最核心的设计思想：<em class="k">语法是中文的，但语义是跟主流语言对齐的</em>。我甚至研究过，把"汉语言"的每一个关键字，都映射到 C 语言的对应概念上：比如"如果"对应"if"，"否则"对应"else"，"循环"对应"for/while"，"函数"对应"function"。</p>
      <p>做这个项目的过程，比我预想的要难得多。因为"翻译"不是简单地换几个词，你得考虑中文的语法习惯，考虑词性、语序，考虑怎么让中文程序员写起来顺手。比如中文里"如果……就……"是一对搭配，"当……时"又是一个搭配，这些语感，都要在语法设计里体现出来。还有中文没有空格分词，那代码里的词怎么切分？这是第一个要解决的问题。我试过按字符、按语义词典、按符号……每一种都有各自的坑。那段时间，我满脑子都是"词法分析""语法树"，连睡觉都在想。</p>
      <p>但我知道，这个项目真正的价值，不在于它能不能做成，而在于我通过它，把我这几年攒的所有东西——易语言的启蒙、Python 的灵活、C++ 的底层、编译原理的深奥——全都拧成了一股绳。它像是我给自己这几年编程生涯交的一份"结业作业"。</p>
      <blockquote>
        有人问我，你花这么多时间研究一门注定没人用的语言，图什么？
        我说，我不图它被用。我图的是，有一天我能拍着胸脯说：我真的搞懂了，编程语言是怎么诞生的。
        <span class="who">—— 关于「汉语言」</span>
      </blockquote>

  <h2 class="ch-title">关于编程，我的一些想法</h2>

  <p class="ch-lead">写了几年代码，我脑子里攒了一堆"自己的想法"。它们未必是对的，也许在很多老程序员眼里还很幼稚。但它们是我自己一路撞出来的，不是从哪本书上背下来的。我把它们写在这里，算是给自己做个记录。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">一、关于中文编程，我真正的看法</h3>
  <p>先说说我最在意的一件事——中文编程。因为我从易语言起步，又自己捣鼓"汉语言"，所以总有人问我：你是不是觉得，编程应该用中文？英文是不是编程的"门槛"？</p>
  <p>我的回答可能跟很多人想的不一样：我不觉得把代码全换成中文，就能让编程变得"简单"。因为编程的难点，从来不在你用的是哪个语言的单词，而在于<em class="k">你得学会用"机器的思维"去思考问题</em>。你得把一个复杂的事情，拆成一步一步、一条一条机器能执行的指令。这个"拆解"的过程，才是真正难的地方。你把它翻译成中文，拆解的难度并不会降低——就像你把一本难懂的书翻译成中文，书还是难懂。</p>
  <p>但是，这不代表中文编程没有价值。它的价值，在于"降低恐惧"。我见过太多人，一看到满屏英文就退缩了，连试都不愿意试。中文编程至少能让这些人迈出第一步——让他们知道，哦，原来"如果"就是"if"，原来我也可以写程序。有了这第一步，他们才会愿意继续往下走，才会发现，原来英文也不是那么可怕。</p>
  <p>所以我对中文编程的态度是：<strong class="k">它是一块敲门砖，而不是一栋楼</strong>。真正的楼，是逻辑，是算法，是解决问题的能力。砖可以让更多人走到门口，但进了门之后，大家学的还是同一套东西。我做的"汉语言"，也是这个思路——它不是一个"替代品"，而是一个"引路人"。</p>
  <p>还有一层，是我藏在心里没怎么跟人说过的心思。我研究中文编程，其实还有一种情结在里面。我总觉得，一门语言，它承载的不只是功能，还有一种"文化气质"。英文编程语言里，到处都是"object""function""class"这些词，它们背后是西方那一套思维习惯。而中文，讲究的是"意会"，是"留白"，是"字里行间"。我常常在想，如果真有人能造出一门真正契合中文思维的语言，那它会不会长得完全不一样？会不会有英文语言里没有的那种"韵味"？这个问题的答案，我还在找。也许永远找不到，但找的过程本身，就很有意思。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">二、英语不是编程的墙</h3>
  <p>很多人，包括我的同学，一听编程要学英语，就吓得不行。我作为一个初中生，英语成绩也不算顶尖，我想说两句公道话。</p>
  <p>编程里用的英语，和考试里考的英语，根本是两码事。编程里的英语，其实是一个一个的"单词标签"，比如"if""for""while""return"。你不需要懂语法，不需要会写作文，你只需要知道"这个单词代表什么意思"。而且，你现在查资料的工具这么方便，一个词不懂，马上就能查到。所以，英语在编程里，更像是一本"词典"的事，而不是一门"学科"的事。</p>
  <p>当然，英语好了肯定有好处。最明显的一个——官方文档。很多编程工具和语言，最权威、最新的资料都是英文的，中文翻译总会慢半拍，而且翻译质量参差不齐。我的英语阅读能力，就是被文档"逼"出来的。一开始看英文文档，一个句子要查好几个词，看得想吐；看得多了，就慢慢顺了。现在我再看到一堆英文文档，虽然不能说全懂，但起码不慌了。它不是我编程路上的墙，而是我翻过去之后，看到了一片更大的风景。</p>
  <p>我想对那些跟我一样，英语不算好但想学编程的人说：别怕。编程不是英语考试，它考验的是你有没有耐心去搞懂一个东西。英语只是一个工具，而且是一个你用得越多越熟练的工具。千万别让它变成你不敢开始的借口。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">三、关于学习：好奇心比教材重要</h3>
  <p>我经常被问到一个问题：你是怎么学会编程的？是不是报了班？是不是看了好多书？</p>
  <p>说实话，我一本编程书都没看完过。我也没报过任何班。我学编程的方式，说出来可能有点"野"——我是被一个个问题"牵着"往前走的。</p>
  <p>我看到一个东西，觉得好奇，就去查；查到了，发现还有更深的，就继续查；查着查着，就想自己动手做；做着做着，又遇到新问题，再接着查……我的知识，就是这样一环扣一环，自己长出来的。它不是一条笔直的路，更像是一棵树，从一个点出发，慢慢长出好多枝丫。</p>
  <p>有人觉得这样学不系统、不扎实。我承认，我确实有很多"知其然不知其所以然"的地方。但我也发现，这种"问题驱动"的学习方式，有个特别好的地方：<em class="k">你学到的每一个知识，都是带着问题来的，你天然就知道它有什么用</em>。不像有些教材，讲了一堆概念，你也不知道学了干嘛，转头就忘。</p>
  <p>所以我对学习的看法是：教材和课程是"地图"，而好奇心是"引擎"。光有地图，车不走；光有引擎，容易迷路。最好的状态，是让好奇心拉着你走，让教材给你指路。我自己这几年的经历证明，这条路是走得通的——哪怕走得歪歪扭扭。</p>
  <blockquote>
    我从来不觉得学习是一件"苦差事"。因为当你真的好奇一件事的时候，弄懂它的过程，跟拆开一个你期盼已久的礼物，是一样的快乐。
    <span class="who">—— 关于学习，我真实的感受</span>
  </blockquote>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">四、关于"安全"：它是一把双刃剑</h3>
  <p>我得花点篇幅，好好说说"安全"这件事。因为我发现，很多人对"安全"的理解，是有偏差的。</p>
  <p>我从小就对"安全"感兴趣。一开始，是因为玩易语言的时候，老跟杀毒软件打交道，一会儿被误报，一会儿看别人讨论什么"病毒""木马""外挂"，觉得这些东西神秘又刺激。后来学了 Python，学了 C++，我更是花了很多时间研究系统、研究网络。有人可能觉得，一个学生研究这些，是不是想干坏事？</p>
  <p>我想在这里说清楚：<em class="k">研究安全，和做坏事，是完全两回事</em>。真正的安全研究，是为了"了解敌人，保护自己"。你得先知道漏洞是怎么形成的，你才能在写代码的时候避免它；你得先知道攻击是怎么发生的，你才能把防御做得滴水不漏。就好比医生要研究病毒，不是为了制造病毒，而是为了治病救人。</p>
  <p>我这些年做项目，把"安全"当成第一要务，就是这个道理。我在"缔造者"里防注入、在"信鸽"里做加密，都不是为了炫技，而是因为我见过太多因为不重视安全而造成的惨痛后果——网站被黑、数据泄露、账号被盗。我自己就亲眼见过一个朋友，因为在一个不安全的网站上输入了自己的账号密码，结果账号被盗，养了好久的游戏号全没了。那种感觉，真的很难受。</p>
  <p>所以我给"安全"下的定义是：它不是一门"攻击"的技术，而是一份"责任"。这份责任，是每一个写代码的人都应该扛起来的。你写的每一行代码，都在替别人保管着什么——也许是一个密码，也许是一条消息，也许是一份数据。你能不能让它们稳稳当当的，是你自己的良心。</p>
  <div class="note reveal">
    <span class="tag">一条底线</span>
    <p>我研究安全，但从不越线。不碰别人没授权的系统，不碰不该碰的数据。这条底线，是我给自己立的规矩。学的东西是工具，用得好不好，全看用的人心里那杆秤。</p>
  </div>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">五、关于工具：我不迷信框架</h3>
  <p>这几年，我身边越来越多人开始用各种框架——写网页用 React、Vue，写桌面用 Qt、Electron。一提到写代码，大家第一反应就是"用哪个框架"。</p>
  <p>我不是说框架不好。框架是前人经验的结晶，用好了能省很多事。但我总觉得，如果一个人只会"用框架"，离了框架就什么都不会，那有点危险。因为框架是会过时的，今天流行的，明天可能就被淘汰了。而底层的东西——算法、数据结构、操作系统、编译原理——这些是不太会过时的。</p>
  <p>所以我给自己定的路子是：<em class="k">先求"懂"，再求"用"</em>。做一个东西，我宁愿先看看它底层是怎么运转的，哪怕多花点时间，也想要那份"掌控感"。这也是为什么我写界面坚持手写、写工具坚持用 C++ 的原因。我知道这条路慢，但我心里踏实——因为我用的每一个工具，我都知道它是怎么来的，我手里握着的是"原理"，而不只是"操作说明"。</p>
  <p>当然，我也在慢慢学着平衡。毕竟，一个人不可能把所有东西都从零造一遍，该用现成的还是要用。但我的原则始终没变：<strong class="k">用框架之前，先搞清楚框架背后是什么</strong>。这样，框架对我来说就不是一个黑箱，而是一个可以随时拆开修理的"工具箱"。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">六、独立开发的孤独，和快乐</h3>
  <p>作为一个自己一个人在电脑前写代码的学生，我太清楚"独立开发"是什么滋味了。</p>
  <p>孤独是常态。周围没人能跟你讨论"指针到底怎么用""这个 bug 到底出在哪"。你遇到问题，只能一个人对着屏幕，一遍遍查资料，一遍遍试。有时候一个问题卡你两天，你问不到人，只能自己死磕。那种感觉，就像在黑夜里一个人摸索着走路，前路一片模糊。</p>
  <p>但快乐也是真的。当你终于把那个卡了两天的问题解决的时候，那种"豁然开朗"的爽快，是任何事都比不上的。当你做的程序第一次跑通的时候，当你写的工具真的帮到别人的时候，你会觉得，之前所有的孤独和死磕，都值了。这种快乐，是那种"与人分享的快乐"完全不同的另一种快乐——它更私密，更纯粹，像只有你自己知道的秘密宝藏。</p>
  <p>还有一个感受，我不知道别的独立开发者有没有——就是那种"世界尽在掌握"的错觉。当你学会了一个又一个东西，你会发现，你对身边这个数字世界的理解越来越深：为什么手机会卡，为什么网站会崩，为什么会有病毒，为什么数据会被偷……这些在别人眼里神秘莫测的事情，在你眼里，慢慢变成了一条条清晰的因果链。这种感觉，让我觉得，我不是在"用"这个世界，而是在"懂"这个世界。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">七、代码是一种表达</h3>
  <p>最后，我想说一个可能有点"文艺"的想法——我觉得，代码其实是一种表达方式。</p>
  <p>作家用文字表达，画家用画笔表达，音乐家用音符表达。而写代码的人，用的是代码。你写一个游戏，是在表达你对"乐趣"的理解；你写一个工具，是在表达你对"效率"的追求；你写一个聊天软件，是在表达你对"连接"的渴望。每一段代码，都藏着写它的人的心思和性格。</p>
  <p>这也是为什么，我一直觉得，看一个人的代码，多少能看出他是个什么样的人。有人写代码工工整整、注释齐全，一看就是严谨的人；有人写代码天马行空、能省则省，一看就是随性的人。我大概是后者偏多一点——我写代码，习惯先把东西跑起来，再回头慢慢收拾。这毛病不好，但我承认，这就是我。</p>
  <p>对我来说，代码不只是谋生的工具，不只是考试的科目，它是我说话的方式。有些话，我说不出来，但写进代码里，就什么都懂了。</p>

</section>

<section class="chapter reveal" id="c7">
  <div class="ch-num">第七章</div>
  <h2 class="ch-title">现在，还有以后</h2>

  <p class="ch-lead">写到这里，前面的路已经讲完了。现在，我想说说眼下的我，和我想去的方向。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">一、学生和程序员，两个身份</h3>
  <p>我现在的日常，是两副面孔来回切换。白天，我是一个普通的初中生，坐在教室里上课，做作业，背课文，参加考试。晚上回到家，写完作业，我就变成了另一个我——一个在代码世界里折腾的程序员。</p>
  <p>说实话，这两个身份有时候会打架。作业多的时候，代码只能往后排；考试前，我连打开电脑的勇气都没有。我的爸妈，一开始对我写代码是持怀疑态度的——他们觉得，这不就是玩电脑吗？跟玩游戏有什么区别？但后来，他们看我写的那些东西，看我整天念叨什么"编译""服务器""加密"，慢慢也明白，我不是在玩，我是在学东西。虽然他们还是经常唠叨"别把眼睛看坏了""早点睡觉"，但我知道，他们心里是为我高兴的。</p>
  <p>我也学会了一件事：<em class="k">课业和代码，不是二选一，而是两条腿</em>。学校的知识，让我有了扎实的基础——数学帮我想清楚逻辑，英语帮我看懂文档，甚至语文，也让我学会怎么把话说清楚。而代码，是学校之外的一片天空，它让我知道，这个世界上还有那么多好玩的东西等着我去探索。两条腿走路，才能走得稳。</p>
  <p>有一次，我们班上有个同学问我：你整天写那些东西，不累吗？我想了想，说，累，但值得。他可能不太懂我在说什么，但那一刻，我知道我在说什么。就像有人喜欢打篮球，有人喜欢画画，有人喜欢唱歌——对我来说，写代码，就是我最大的爱好。做自己喜欢的事，再累也是甜的。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">二、这条路上，我遇到过的人</h3>
  <p>虽然这条路大部分时候是孤独的，但我也遇到过一些让我心里暖暖的人。</p>
  <p>有网上的陌生人。我初学易语言的时候，在一个论坛上问了一个特别蠢的问题——蠢到什么程度呢，就是那种你都不好意思再问第二遍的问题。但有个网友，特别耐心地回了我的帖子，还给我讲了半天原理。后来我慢慢学会了，就很少再问别人问题了，但我一直记得那个网友。在这个人人都在赶路的时代，有人愿意停下来，为一个素不相识的小孩讲清楚一个基础得不能再基础的问题，这件事本身，就让我觉得这个世界挺好的。</p>
  <p>还有我的信息技术老师。他可能是全校唯一一个知道我在写代码的老师。有一次，我拿一个自己写的小程序给他看，他看完之后，沉默了一会儿，跟我说了一句话：好好学，这条路，你走得下去。就这一句话，我记到现在。也许在别人听来很平常，但对我来说，那是来自"大人世界"的第一次认可。</p>
  <p>当然，也有看我不顺眼的人。有同学觉得我装，有亲戚觉得我"不务正业"，还有人说风凉话："一个学生，写什么代码，能写出花来？"刚开始听到这些，我会难过，会怀疑自己。但现在我慢慢想通了：<em class="k">别人的评价，是别人的课题；我要不要继续走，是我的课题</em>。只要我自己知道自己在干什么，别人说什么，随他去吧。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">三、我想去的地方</h3>
  <p>关于未来，其实我想得不算特别多，但我心里有几件想做的事，是很清楚的。</p>
  <p>第一，我想把"缔造者"做完。我想看到有一天，真的有人用它做出了自己的网站，而且用得很开心。第二，我想把我的那个 IDE 一直做下去，哪怕只做到支持几十种语言，我也满足了——因为它是我"从头造轮子"的证明。第三，我想把"汉语言"研究得更深一点，也许有一天，我真的能写出一门"长得像中文、内核又严谨"的语言来。这些目标，每一个都很大，每一个都不容易，但我有的是时间，也有的是耐心。</p>
  <p>我还想去看更远的世界。我想真正搞懂那些我现在还只是一知半解的东西——操作系统是怎么设计的？编译器是怎么优化的？网络协议是怎么一步步演变成今天这个样子的？这个世界的技术，就像一座座高山，我现在才刚走到山脚，抬头看，山顶还藏在云里。但没关系，山就在那里，我走一步，就近一步。</p>
  <p>我常常想起小时候看 4399 的那个下午。那时候的我，怎么也想不到，一台破电脑、一个叫易语言的东西，会把我带到这么远的地方。如果有一天，我能回到过去，告诉四年级那个正在偷偷玩电脑的小孩：别急，你以后会走得很远。我想他一定会很惊讶，也很开心。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">四、写给同样好奇的人</h3>
  <p>最后这一段，我想写给那些跟我一样，对电脑、对代码充满好奇，却还在犹豫要不要开始的人。</p>
  <p>如果你问我，学编程难不难？我会说，难，真的难。但我会补一句：也没有你想象的那么难。它难的，不是那些看不懂的英文，不是那些复杂的语法，而是你有没有一颗愿意"死磕"的心。你愿意为了一个问题，查上一个晚上的资料吗？你愿意为了一个 bug，盯着屏幕看上两个小时吗？你愿意在一次次的失败里，爬起来继续吗？如果你愿意，那你就已经具备了一个程序员最重要的东西。</p>
  <p>还有，别怕起步晚，也别怕起步"土"。我四年级的时候，用的还是很多人瞧不起的易语言；我连 Python 的语法都是东拼西凑学来的。但这都不妨碍我一路走到现在。重要的不是你的起点有多高，而是你有没有一直往前走。</p>
  <p>如果你身边没有人懂代码，没关系。互联网上有一整个世界的人在陪你。遇到问题，去搜，去问，去试。你搜到的每一个答案，问到的每一个人，都会成为你这条路上的"网友老师"。</p>
  <p>最后送你一句我自己这几年的切身体会：<strong class="k">代码这个东西，你越怕它，它越吓人；你越敢碰它，它越温柔</strong>。它不会因为你第一次写就嘲笑你，也不会因为你写得丑就抛弃你。它只会安安静静地待在那里，等你一遍一遍地试，然后，在你终于把它弄明白的那一刻，给你一个大大的惊喜。</p>
  <p>我还想多说一句：学编程，永远不怕晚，也永远不怕"笨"。我见过六年级才开始学编程的人，也见过工作之后才转行学代码的人，他们一样学得很好。怕的不是"起步晚"，怕的是"不敢开始"。只要你敢点开那个编辑器，敲下第一行代码，你就已经赢过了那些只会"想想"的人。</p>
  <blockquote>
    我不是天才，也不聪明。我只是比别人多了一点好奇，多了一点死磕。而这两样东西，每个人都能有。
    <span class="who">—— 写给自己，也写给屏幕前的你</span>
  </blockquote>

  <h2 class="ch-title">那些第一次</h2>

  <p class="ch-lead">人这一辈子，会经历很多"第一次"。第一次骑车，第一次出远门，第一次喜欢一个人。而对一个写代码的人来说，也有好多好多的第一次。我把我记得住的，挑几个写下来。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">第一次，把程序发给别人</h3>
  <p>那是我刚学会用易语言做窗口程序的时候。我写了一个特别特别简单的小东西——一个窗口，上面一行字，一个按钮。字是我自己定的，按钮点了会再弹出一个窗口。就这么个玩意儿，我翻来覆去改了好几遍，编译了，又编译，最后终于满意了。</p>
  <p>然后我做了人生中第一个"发布"动作——把它发给了一个同学。那时候还没有微信这么方便，我是用 QQ 传的文件。传的时候，我心跳得特别快，手指头都在抖。</p>
  <p>过了大概十分钟，他回了消息。就两个字："你写的？"我说，是啊。他又问："真的假的？"我说，真的。他沉默了一会儿，发过来一个竖起大拇指的表情。</p>
  <p>就那一个大拇指，我盯着屏幕看了好久，心里美滋滋的。虽然我知道，那个程序在真正的程序员眼里，幼稚得像个刚学会走路的孩子。但那是我第一次尝到"作品被认可"的滋味。那种滋味，一直甜到我心里，很多年都没有散。</p>
  <p>从那以后，我养成了一个习惯——每做出一个新东西，就想找个人"显摆"一下。这个习惯，被我妈吐槽过很多次，说我"像刚下蛋的母鸡，咯咯咯叫个不停"。但我觉得，这没什么不好的。做出来的东西，有人看，有人懂，才更有动力做下去，不是吗？</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">第一次，真正"修好"一个 bug</h3>
  <p>学过编程的人都知道，程序出问题，不叫"出问题"，叫"bug"。这个词的来历还挺有意思——据说以前，一台大型计算机出了故障，工程师打开一看，发现是一只飞蛾卡在继电器里，把电路弄短路了。从那以后，"虫"（bug）就成了程序错误的代称。我第一次听到这个故事的时候，觉得又好笑又神奇——原来我们天天说的"bug"，真的是从一只虫开始的。</p>
  <p>我刚学编程那会儿，遇到的"bug"，基本靠"瞎试"来修。哪里报错了，我改一下，不行再改一下，像猜谜一样。运气好的时候，改两下就好了；运气不好的时候，改一晚上都好不了。</p>
  <p>后来有一次，我在写一个 Python 程序的时候，遇到一个特别诡异的 bug：程序明明逻辑没错，但结果就是不对。我翻来覆去看了半天，怎么也找不到问题。最后，我实在没办法，就把代码一行一行地加"print"，把每一行的中间结果都打印出来，一点点往前推。</p>
  <p>推到其中一行的时候，我愣住了——那里有个变量，我明明赋值了，可打印出来是空的。我再仔细一看，好家伙，原来是我手滑，把一个变量的名字拼错了。一个字母之差，一个是"result"，一个是"resutl"。就因为这一个字母，程序跑了半天，全白跑。</p>
  <p>那一刻，我哭笑不得，但也忽然明白了一个道理：<em class="k">bug 不是"程序坏了"，而是"我哪句话说错了"</em>。程序本身是诚实的，它不会骗你，它只是严格地执行你写的话。你说错了，它就照着错的执行。所以找 bug，本质上不是"修电脑"，而是"反思自己"。</p>
  <p>从那以后，我再遇到 bug，不再像没头苍蝇一样乱撞了。我会先把"最可能出错的地方"找出来，再一点点排查。这个习惯，让我后来少走了好多弯路。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">第一次，熬夜</h3>
  <p>我的第一次熬夜，是为了一个程序。</p>
  <p>那是我在钻研一个比较复杂的项目，白天上了一天课，晚上回到家，吃了饭，就开始弄。弄着弄着，就忘了时间。等我反应过来，窗外的天已经黑透了，客厅里爸妈的电视声也停了，整个家安安静静的。</p>
  <p>我看了看表，十一点半。我对自己说，再做一会儿，把这个弄完就睡。结果，那个"一会儿"，一下子就到了凌晨一点多。中间的过程我已经记不太清了，只记得我一直在改代码、运行、看结果、再改，像一个不知疲倦的循环。</p>
  <p>然后，忽然之间，那个程序跑通了。屏幕上出现了我想要的结果。那一刻，我长舒了一口气，靠在椅子上，看着天花板，心里有种说不出的感觉。不是狂喜，不是激动，而是一种很平静的满足——像爬了很久的山，终于登顶了，山风迎面吹来，世界一下子安静了。</p>
  <p>我轻手轻脚地去洗了把脸，躺到床上，脑子里还在想那个程序。我迷迷糊糊睡着之前，还在想：原来电视里演的那些"熬夜写代码的程序员"，是真的存在的。而我自己，也变成了他们中的一员。</p>
  <p>第二天早上，我被我妈叫醒的时候，顶着一对黑眼圈。我妈问我：昨天晚上又玩电脑了？我说，不是玩，是写代码。我妈叹了口气，说：写代码也不用写那么晚吧？我嘴上应着"知道了知道了"，心里却在想：她不懂，那种感觉，就像你追一部特别好看的剧，你怎么忍得住不去看下一集呢？</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">第一次，拆电脑</h3>
  <p>我家的那台老电脑，用久了，就越来越卡。开机要一分多钟，打开个网页都费劲。我实在受不了了，就想着，能不能自己动手，让它变快一点？</p>
  <p>我在网上查了一晚上，最后得出结论：两个办法。一个是加内存条，一个是换固态硬盘。我看了半天教程，觉得自己能行，就偷偷下单买了一个二手的固态硬盘（那会儿的我还不太会分辨真假，差点买到扩容盘，这个后面再说）。</p>
  <p>东西到手之后，我找了一把螺丝刀，把电脑机箱的侧板拆了下来。那一瞬间，我看到了电脑的"内脏"——一块绿色的主板，上面插着各种大大小小的零件，有的贴着小风扇，有的插着长长的条子，还有一堆粗细不一的线，绕在一起，看得我头皮发麻。</p>
  <p>我举着螺丝刀，手都在抖。我生怕自己一个不小心，把哪个零件弄坏了，那可是我家唯一的电脑啊。我对着教程，一条线一条线地认：这个是电源线，这个是数据线，这个是主板供电……认了足足有一个小时，才敢下手。</p>
  <p>装固态硬盘的过程，其实不复杂——就是找个地方固定好，插上数据线和电源线。但对我这个第一次拆电脑的人来说，那真是每一步都像在拆炸弹。装完之后，我小心翼翼地开机。屏幕亮起来的那一刻，我悬着的心才终于放了下来。</p>
  <p>然后，奇迹发生了。以前开机要一分多钟的电脑，现在十几秒就进去了。打开软件，也是"嗖"的一下。我愣在那里，看着飞快弹出的桌面，心里只有一个念头：<em class="k">原来，我不仅能"用"电脑，我还能"治"电脑</em>。</p>
  <p>那次拆电脑的经历，让我对"硬件"这个词，有了第一次真正的认识。以前我觉得，电脑就是一块屏幕加一个机箱；那次之后我才知道，电脑是一个由无数零件精密协作的机器，而每一颗螺丝、每一根线，都有它的位置和使命。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">第一次，做出"火绒风格"的界面</h3>
  <p>这个"第一次"，得从我的一个审美偏好说起。我特别喜欢一个叫"火绒"的安全软件。喜欢它，不只是因为它好用、不流氓，更是因为它的界面——干净、简洁、大方，没有那些花里胡哨的东西。我一看到它的界面，就觉得心里舒服。</p>
  <p>然后我就产生了一个念头：我能不能用 C++ 和 Windows API，做出一个"火绒风格"的界面？就是那种左边一竖排功能菜单，右边是内容区，整体颜色简单大方，看起来特别"专业"的界面。</p>
  <p>说干就干。我用 CreateWindow 创建了一个大窗口，然后在上面画了一个左侧的菜单栏，放了好几个"按钮"（其实是用自绘的方式画的，看起来像按钮的东西）。右边留了一块内容区。我又给整个界面配了一套配色——深色的侧栏，浅色的主区，加上一点点红色的点缀。最后，为了让界面更有"质感"，我还特意加了圆角和阴影的效果。</p>
  <p>当那个界面第一次跑起来的时候，我自己都惊呆了。它看起来，真的有几分"专业软件"的样子了。我盯着它看了好久，又把它截图存了下来。那天晚上，我躺在床上，还在想：原来我也有能力，做出"好看"的东西。</p>
  <p>这个经历让我明白了一件事：<em class="k">界面不是随便画画的，它是软件的一张"脸"，是你跟用户说的第一句话</em>。一个软件好不好用，界面占了很大一部分。而我，从那天起，也有了自己的审美追求——不追求花哨，只追求舒服。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">第一次，在网上帮别人解决问题</h3>
  <p>这件事，说来有点意思。我平时在论坛和贴吧潜水，看别人讨论技术问题。有一次，我看到一个帖子，有人问了一个问题——那个问题，恰恰是我前几天刚踩过的坑。我一看，嘿，这个我会！</p>
  <p>我犹豫了一下，然后一个字一个字地打了一篇回复，把自己踩坑的过程、解决方法、注意事项，全写了上去。写完之后，我检查了好几遍，确定没有错别字，才点了"发送"。</p>
  <p>发完之后，我心里七上八下的，时不时就刷新一下页面，看看有没有人回复我。过了大概一个小时，有人回复了，是楼主，他说："试了，真的好了，谢谢！"</p>
  <p>就这一句话，让我高兴了整整一个晚上。我忽然觉得，自己这几年学的东西，不只是"自娱自乐"，它还能实实在在地帮到别人。那种"被需要"的感觉，是玩游戏、看电视都给不了的。</p>
  <p>从那以后，我遇到自己会的问题，只要看到了，就会去答一答。我也慢慢体会到，为什么那个当初给我解答问题的网友，愿意花时间帮我了——因为帮别人解决一个问题，自己心里也是甜的。这大概就是"赠人玫瑰，手有余香"吧。</p>
  <div class="note reveal">
    <span class="tag">第八章小结</span>
    <p>回头数了数，我这几年的"第一次"，还真不少。第一次发程序、第一次修 bug、第一次熬夜、第一次拆电脑、第一次做界面、第一次帮人……它们像一颗颗珍珠，被"编程"这根线串在一起，成了我一段特别珍贵的记忆。</p>
  </div>

  <h2 class="ch-title">我家的那台电脑</h2>

  <p class="ch-lead">写代码的人，总得有一台电脑。我的"第一台搭档"，就是我家客厅里那台又老又卡的台式机。这一章，我想好好写写它，也写写我在这台电脑上学到的东西。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">一、一台"来历不明"的电脑</h3>
  <p>我说过，我家那台电脑是别人家淘汰下来给的。它到底用了几年，没人说得清。它的机箱是银灰色的，侧面有一块透明的塑料板，能看到里面——但里面也没什么好看的，就是一层灰。</p>
  <p>它的配置，搁到现在看，寒酸得让人心酸。CPU 是很老很老的双核，内存好像只有两个 G，硬盘是那种转起来"咔咔"响的机械硬盘，一开机就嗡嗡嗡地转。显卡？基本等于没有，玩个网页游戏都要把画质调到最低。显示器是那种又厚又重的老式液晶屏，分辨率低，颜色还有点发白。</p>
  <p>但就是这样一台电脑，承载了我几乎全部的童年幻想。我在它上面第一次玩到了赛尔号，第一次下载了易语言，第一次写出了"你好，世界"，第一次熬夜调试程序。它就像一头任劳任怨的老黄牛，虽然慢，虽然卡，但从来没在我最需要它的时候"罢工"过。</p>
  <p>我对这台电脑的感情，是很复杂的。有时候我会嫌它慢，嫌弃它开个程序要等半天；但更多的时候，我会心疼它——你看它，风扇呼哧呼哧地转，机箱热得烫手，还在努力地跑我那些越来越大的程序。它大概也知道，自己老了，跑不动了，但它还是在尽力撑着，就像在说：主人，你尽管写，我还能扛。</p>
  <p>后来我学会了一个词，叫"榨干性能"。我觉得用在我家这台电脑上，再合适不过了。我为了让它跑得更快一点，想尽了一切办法：关掉开机启动项、清理垃圾文件、把特效全关掉、甚至研究过超频（后来因为怕把它烧了，放弃了）。每优化一点点，我就特别有成就感，好像不是我伺候它，而是我跟它一起并肩作战。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">二、第一次知道"扩容盘"</h3>
  <p>前面我提到过，我买过一个二手的固态硬盘，差点买到"扩容盘"。这个坑，我到现在还记得清清楚楚，值得专门写一笔。</p>
  <p>那时候我攒了好久的零花钱，想给电脑升个级。我在网上淘了一个"号称"容量很大的固态硬盘，价格便宜得让人心动。我兴冲冲地把它装上去，开机一看，容量确实对，文件也确实能存进去。我当时还美滋滋的，觉得自己捡了个大便宜。</p>
  <p>结果，用了没几天，问题来了。我先是想往里面复制一个大文件夹，复制到一半，突然报错，说"磁盘空间不足"。我一看，明明还有几百个 G 啊？怎么就不足了？</p>
  <p>我又试着往里存了一部电影，存进去了，能放。可再存一部，就又开始报错了。我越想越不对劲，就去网上查。一查，我整个人都傻了——原来我买的是"扩容盘"。什么叫扩容盘？就是黑心商家把一个小容量的盘，通过修改主控参数，伪装成一个大容量的盘。你在电脑上看，它显示有几百个 G，但实际上，它可能只有几十个 G，甚至更少。你以为存进去的文件，其实被"挤"在了那一小片真实空间里，超出了真实容量的部分，全是假的——存进去就丢，或者根本存不进去。</p>
  <p>知道真相的那一刻，我气得饭都吃不下。不只是心疼钱，更是心疼我那几天辛辛苦苦存的资料。我把能找回来的文件抢救了一遍，然后当机立断，把那块"扩容盘"拔下来，扔进了抽屉里，再也没用过。</p>
  <p>这件事给我上了特别深刻的一课：<em class="k">便宜没好货，天上不会掉馅饼</em>。尤其是在这种看不见摸不着的"科技产品"上，更要擦亮眼睛。从那以后，我买任何电子产品，都要先查半天评测，学会看参数、看口碑、看真伪鉴别的方法。我甚至还专门研究过，怎么鉴别扩容盘——用什么软件测真实容量，怎么看主控芯片，怎么看固件。这些知识，虽然听起来冷门，但都是那次"吃亏"换来的。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">三、给电脑"看病"</h3>
  <p>电脑用得久了，总会出各种毛病。我家那台老电脑，几乎把能得的"病"都得了一遍：开机蓝屏、系统崩溃、网络连不上、风扇狂转、文件打不开……而给这台电脑"看病"，就成了我的"实习课"。</p>
  <p>我第一次解决的系统问题，是"开机很慢"。那时候电脑开机要一分多钟，我实在受不了了，就研究起"开机启动项"来。什么叫开机启动项？就是电脑开机的时候，会自动运行的那些程序。有的程序是系统必需的，有的却是软件自己加进去的——比如你装了个什么软件，它为了"方便"你，就偷偷把自己设成开机自启，结果电脑一开机，一堆程序抢着启动，能不慢吗？</p>
  <p>我打开了系统自带的"任务管理器"，又研究了"运行"里的一些命令，把那些没用的开机启动项一个一个地禁用掉。禁用完，重启，开机速度快了一大截。我高兴坏了，觉得自己像个"电脑医生"，对症下药，药到病除。</p>
  <p>后来我还遇到过更麻烦的问题。有一次，电脑怎么也连不上网，路由器重启了也不行。我排查了半天：网线插没插好？检查了。路由器设置对不对？也检查了。IP 地址对不对？都检查了。最后我灵机一动，打开命令行，输入了一个叫"ipconfig"的命令，看了一下网络配置，然后又试了"ping"命令，去"ping"一下网关。这一"ping"才发现，原来是电脑的 IP 地址跟另一个设备冲突了。我改了设置，网络就恢复了。</p>
  <p>那一次经历，让我第一次体会到"命令行"的威力。以前我觉得，命令行就是那个黑乎乎的窗口，看着就吓人；但那一次之后我才发现，命令行其实是一个特别强大的"工具箱"，里面藏着很多系统自带的神奇命令。从那以后，我开始研究命令行，从最简单的 dir、cd，到后来的 ipconfig、ping、netstat、tasklist……一个个命令摸过去。我越来越觉得，<em class="k">会玩命令行的人，才算真正摸到了电脑的"方向盘"</em>。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">四、键盘、鼠标和"手感"</h3>
  <p>除了主机，我家的"外设"也很寒酸——一个用了不知道多少年的键盘，按键上的字都磨掉了一半，只能靠记忆盲打；一个滚轮鼠标，滚动的时候还会"咯噔咯噔"响。但就是这套"老古董"，陪我打完了不知道多少盘游戏，敲完了不知道多少行代码。</p>
  <p>我第一次意识到"手感"这件事，是在我试过别人的键盘之后。那是一个同学的爸爸的机械键盘，按下去"咔哒咔哒"响，回弹特别有力，打字的手感跟我家那软塌塌的键盘完全是两个世界。那一刻我才知道，原来键盘和键盘之间，差别能这么大。</p>
  <p>但我也很清楚，以我家的条件，配一套好外设，暂时还不太现实。所以我就想了个"土办法"——在网上找那种模拟机械键盘音效的软件，打字的时候配上"咔哒咔哒"的声音，假装自己在用机械键盘。虽然有点自欺欺人，但别说，听着那声音，我写代码的心情还真好了不少。</p>
  <p>说起键盘，我还想说说打字。我练打字，是在游戏里练出来的——玩那种需要跟队友聊天的游戏，别人打字飞快，我打字慢吞吞的，一着急就乱按。为了不被队友嫌弃，我偷偷练起了盲打。从"一个手指头戳"到"十个手指头各就各位"，我练了挺长时间。等到我能闭着眼睛飞快打字的时候，我才发现，这个技能在写代码的时候，简直是如虎添翼——因为写代码的时候，脑子里想的和手上打的，必须要同步，手速跟不上，思路就断了。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">五、网速，和那个"猫"</h3>
  <p>说到上网，我家最早的时候，是插那种像 U 盘一样的"上网卡"的，信号差，网速慢。后来才终于拉上了宽带，装了一个"猫"（调制解调器），还配了一个路由器。装宽带那天，我特别激动，因为我终于可以"无限畅游"互联网了——当然，我妈后来给我限了时，这又是另一回事了。</p>
  <p>装完宽带之后，我干的第一件事，就是下载易语言的新版本。以前用上网卡，下几十兆的东西要下两三天；现在用宽带，几分钟就下完了。我看着那个下载进度条飞快地往前走，第一次真切地感受到了"网速"这个词的分量。</p>
  <p>后来我还自学了怎么进路由器后台。那个后台页面，密码就印在路由器背面，一串数字加字母。我记下来之后，就总爱进去看：谁连了我家的网、网速怎么样、能不能把某个设备禁了。有一回，我发现邻居家蹭了我家的 WiFi，气得我直接把他拉黑了。现在想想，那个拉黑操作，可能是我人生中第一次"行使管理员权限"吧。</p>
  <p>研究网速的过程，让我慢慢明白了"网速"和"带宽"的区别，明白了为什么下载是"下"而不是"上"，明白了延迟和速度是两码事。这些知识，在别人看来可能很枯燥，但我却觉得特别有意思——因为它们解释了我天天在用、却一直没想明白的事情。</p>
  <div class="note reveal">
    <span class="tag">关于硬件，我想说的</span>
    <p>很多人觉得，编程是"软件"的事，跟"硬件"没关系。但我的体会是，不懂一点硬件，你写代码的时候，就像闭着眼睛开车——你不知道你的程序在什么"车"上跑，也不知道它能跑多快、会不会"抛锚"。我花了很多时间跟硬件打交道，虽然走的弯路不少，但这些弯路，让我对"电脑"这个整体，有了更完整的认识。</p>
  </div>

<section class="chapter reveal" id="c10">

  <h2 class="ch-title">游戏教我的事</h2>

  <p class="ch-lead">我这一路走来，起点是游戏。很多人觉得游戏是"玩物丧志"，但我必须说句公道话——如果我没有玩过那些游戏，我可能根本不会对编程产生兴趣。而且，游戏里藏着的道理，比很多人想象的多得多。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">一、从"玩"到"想"</h3>
  <p>四年级那会儿，我玩游戏纯粹是"玩"——点开、进去、打怪、升级，乐此不疲。但玩着玩着，我的注意力就开始跑偏了。我越来越好奇的不是"怎么玩得更好"，而是"这个游戏到底是怎么做的"。</p>
  <p>我记得有一次玩赛尔号，我要抓一只精灵。那只精灵的捕捉概率特别低，我抓了十几次都没抓住。我一边抓一边想：这个"概率"到底是怎么回事？为什么有时候一次就抓住了，有时候十几次都抓不住？是随机的吗？还是有什么我不知道的规律？</p>
  <p>那时候我还不懂什么叫"随机数"，但这个问题在我心里扎了根。后来我学了编程，才明白——游戏里的概率，其实是程序用"随机数"算出来的。电脑会在一个范围内随机生成一个数，如果这个数落在某个区间里，就算你"抓到了"，否则就算"没抓到"。就这么简单。而我那时候觉得神秘得不得了的"概率"，说白了，就是一行"rand()"或者"random()"的事。</p>
  <p>想通了这件事之后，我看游戏的眼神都不一样了。以前我觉得游戏是"魔法"，现在我知道，游戏是"算法"。每一个在我眼前活蹦乱跳的角色、每一次血条的变化、每一件装备的掉落，背后都是一行一行的代码在运作。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">二、游戏里的那些"数学"</h3>
  <p>等我学了编程，再回头看那些我玩过的游戏，我发现它们简直是一座"数学宝库"。</p>
  <p>先说伤害计算。我玩过一个叫造梦西游的游戏，里面角色的攻击力、防御力、技能加成，算起来一套一套的。以前我玩游戏，只管闷头打，从不算这些。学了编程之后，我忍不住去琢磨：如果让我来设计这套伤害公式，我会怎么写？大概就是——先把基础攻击力取出来，加上装备加成，再乘上技能倍率，最后减去对方的防御，得出实际伤害。如果再加上"暴击"，那就是再乘一个暴击系数，而这个暴击是否触发，又是一个随机数的事。</p>
  <p>想明白这些之后，我甚至自己动手，用 Python 写过一个简单的"伤害计算器"——你输入攻击力、防御力、技能倍率，它就能算出你这一下能打多少血。虽然这个计算器幼稚得可笑，但我写它的时候，心里特别高兴。因为那一刻，我不是在"玩"游戏，而是在"拆"游戏——我把游戏的一小块"内脏"掏出来，放在了阳光下。</p>
  <p>再说排行榜。很多游戏都有排行榜，谁的分数高，谁就在前面。我以前只知道盯着排行榜看，看看自己排第几。学了编程之后我才知道，排行榜的背后是"排序算法"——程序要把所有玩家的分数拿出来，排一个序，再显示出来。而排序算法，是计算机科学里最经典的入门知识之一。什么冒泡排序、选择排序、快速排序，各有各的脾气。我后来学这些算法的时候，脑子里总是不自觉地浮现出游戏排行榜的样子——原来我天天看的那个榜，背后藏着这么深的知识。</p>
  <p>还有背包系统。玩 RPG 游戏的人都知道，背包里的东西是按格子放的，有的东西能叠加，有的不能，装满了就装不下了。我以前只觉得这个设计很烦人，学了编程之后我才发现，背包的底层就是一个"数组"或者"列表"——程序用索引来管理每一个格子，你捡起一件东西，就是往数组里塞一个元素；东西满了，就是数组满了。就这么简单。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">三、为什么游戏会"上瘾"</h3>
  <p>有一段时间，我特别沉迷一个游戏，一玩就是几个小时，停不下来。我爸妈很担心，我自己也有点慌——明明知道该去写作业了，但手就是离不开鼠标。</p>
  <p>后来我学了编程，开始研究"为什么游戏会让人上瘾"这个问题。我查了很多资料，慢慢发现，游戏让人上瘾，不是因为它"好玩"，而是因为它设计了一套特别精巧的"奖励机制"。</p>
  <p>你想想，游戏里是不是总有这样的设计：你打了一个怪，掉了一件装备；你完成了一个任务，领到了经验和金币；你升了一级，解锁了新技能。这些"奖励"，一个接一个，像糖豆一样撒给你，让你永远有"下一个目标"。而游戏设计者还特别狡猾——他们不会让你轻轻松松就拿到奖励，而是让你"差一点点就拿到了"。就是这个"差一点点"，让你忍不住再来一把，再来一把，再来一把。</p>
  <p>在编程里，这个机制叫"循环"——一个接一个的目标，形成一条永不停歇的循环。而支撑这个循环的，是"条件判断"和"随机数"的组合。我以前只觉得游戏好玩，学了编程之后我才明白，好玩不是天上掉下来的，是设计者精心算好的。</p>
  <p>想明白这件事之后，我再玩游戏，心态就变了。我不是不想玩了，而是我开始"带着显微镜"去看它——这个奖励设计得好不好？那个概率调得合不合理？如果我来做，我会怎么设计？有时候我还会忍不住吐槽：这个设计也太偷懒了吧？</p>
  <p>也是从那时候起，我给自己立了一个规矩：游戏可以玩，但要"限时"。因为我太清楚它背后那套"循环"的把戏了——<em class="k">我不想被我自己研究的机制，反过来控制住</em>。这句话，现在说起来轻松，但当时能想通，我真的用了很久。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">四、从"玩游戏"到"做游戏"</h3>
  <p>玩够了、想通了、研究透了，剩下的，自然就是"做"了。</p>
  <p>我最早的游戏尝试，是在易语言里做的。我做过一个"猜数字"的游戏：程序随机想一个 1 到 100 之间的数，你在编辑框里输入你猜的数，程序告诉你"大了"还是"小了"，直到你猜对为止。就这么一个简单得不能再简单的游戏，我加上了计次、加上了记录"最快几次猜中"的功能，玩得不亦乐乎。</p>
  <p>后来用 Python 的 pygame，我又做了一些"更像游戏"的东西——贪吃蛇、飞机大战。做这些游戏的过程，让我最深地体会到了一句话：<em class="k">做游戏，和玩游戏，完全是两码事</em>。玩游戏的时候，你享受的是"结果"；做游戏的时候，你操心的是"过程"——这个角色怎么移动？碰到边界怎么办？怎么检测碰撞？分数怎么算？重新开始怎么处理？一桩桩、一件件，全是细节。</p>
  <p>我记得做飞机大战的时候，最难的是"碰撞检测"——你怎么知道子弹打中了敌机？最简单粗暴的办法，是判断两个物体的坐标有没有"重叠"。可我的子弹和敌机都是各种形状，直接比坐标特别容易出错。我在网上查了好久，最后才学会用"矩形碰撞"的思路——把每个物体都当成一个矩形，然后判断矩形之间有没有相交。这个办法不算精确，但够用、高效，是很多游戏都在用的"土办法"。</p>
  <p>当我终于把飞机大战做完，能控制小飞机躲子弹、打敌机、得分、爆出"GAME OVER"的时候，我长舒了一口气。那架用像素拼出来的小飞机，丑是丑了点，但它是我的。我可以把它发给任何人，告诉他们：这是我做的游戏。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">五、游戏背后更大的世界</h3>
  <p>说到做游戏，我还得提一个我特别感兴趣的领域——游戏里的 AI。你看很多游戏里的怪物，它们会自己走动、自己追着你打，有的还会"绕路"。这是怎么做到的？</p>
  <p>我研究过一点点。最简单的"自动寻路"，就是让怪物朝着玩家的方向一直走，碰到障碍就换个方向。再高级一点的，是让怪物用"最短路径"来找你——这就是著名的 A* 算法，我在网上看过它的讲解，虽然没完全看懂，但我知道了大概的思路：把地图分成一个个格子，然后从起点开始，一层一层地往外"探"，找到一条从起点到终点最短的路径。这个算法的思想，让我叹为观止——原来"聪明"的怪物，背后也是一套精心设计的数学方法。</p>
  <p>我还幻想过，有一天要做一个"无限地形"的游戏——就是那种你一直走，地图一直生成，永远走不到头的游戏。实现它的关键，是一种叫"噪声算法"的东西，它可以生成看起来特别自然的起伏地形。虽然我现在还没有真正做出来，但这个念头，一直藏在我心里。</p>
  <p>你看，游戏的世界，其实是一个巨大的入口。你顺着"好玩"往里走，会碰到数学，碰到算法，碰到 AI，碰到编程。这些知识，随便哪一样，都够你学一辈子。而它们的起点，可能只是你小时候，在 4399 上点开的一个小游戏。</p>

    <span class="who">—— 关于游戏，我的真实想法</span>

  <h2 class="ch-title">不务正业的探索</h2>

  <p class="ch-lead">写代码之余，我还干过一堆"不务正业"的事——研究注册表、折腾系统文件、写批处理脚本、修电脑。这些事，看着跟"编程"没什么关系，但它们其实是同一件事：好奇，然后动手去搞懂它。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">一、注册表，那个"神秘数据库"</h3>
  <p>我第一次听说"注册表"这个词，是在研究"开机启动项"的时候。当时网上有人说，某些开机启动项藏在注册表里。我当时就想：注册表是什么东西？听着怎么这么神秘？</p>
  <p>后来我照着网上的教程，打开了注册表编辑器。那个界面，密密麻麻的全是文件夹一样的"键"，一层套一层，看得我头皮发麻。我一开始完全不敢动，生怕点错一个，电脑就报废了。</p>
  <p>但我又实在好奇，就小心翼翼地，只点开那些教程里提到的路径，慢慢看。慢慢地，我大概明白了——注册表，其实就是 Windows 系统用来记录"配置信息"的一个大数据库。你的电脑装了哪些软件、开机要启动什么、桌面背景是什么、文件默认用什么打开……这些零零碎碎的设置，全都记在注册表里。它就像是 Windows 的"病历本"，记录着这台电脑的一切"身体状况"。</p>
  <p>想通这一点之后，我胆子大了点，开始"只读"式地翻看注册表，看看里面都有什么。我发现里面有些键值，名字起得特别直白，比如某个软件装在哪、版本号多少，一眼就能看懂；有些键值则全是乱码一样的字符，完全不知道是干嘛的。每搞懂一个键的含义，就像在解一道谜，特别有成就感。</p>
  <p>当然，我也有"翻车"的时候。有一次，我手痒，想清理一下注册表里的"垃圾"，结果一个手滑，把一个不该删的键给删了。删完我就后悔了，心里七上八下的，生怕电脑出问题。还好，我删的那个键影响不大，电脑还能正常用。但那次之后，我再也不敢乱动注册表了——我给自己立了个规矩：<em class="k">不懂的东西，先弄懂再动手；没把握的操作，先备份再做</em>。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">二、系统里的那些"神秘文件"</h3>
  <p>除了注册表，我还特别喜欢研究 Windows 系统文件夹里的那些文件。什么 System32、Program Files、AppData……每一个文件夹，都是一片"新大陆"。</p>
  <p>我最先研究的是 System32——一个传说中"不能乱删"的文件夹。网上流传着一个梗：删了 System32 就能让电脑变快（其实是会崩溃）。我当然不会去删，但我很好奇，里面到底装了什么？我打开一看，好家伙，成千上万个文件，后缀名五花八门：.dll、.exe、.sys、.dat……我一个个点开看属性，发现它们大多是系统运行需要的"零件"。</p>
  <p>其中我最感兴趣的，是 DLL 文件。我查了很久才搞明白：DLL 全称是"动态链接库"，它就像是一个"公共工具箱"，里面装着一堆函数。多个程序可以共用这一个工具箱，这样就不用每个程序都自己带一套工具了，省空间、省内存。我后来用 C++ 写程序的时候，还真的自己写过 DLL，把一个功能封装进 DLL 里，然后让另一个程序调用它。当那个程序成功调用了我写的 DLL 里的函数时，我特别得意——因为这意味着，我也能给别人提供"公共工具"了。</p>
  <p>我还研究过 .sys 文件，知道那是系统驱动程序，是操作系统跟硬件打交道的"翻译官"。研究过 .ini 和 .config 文件，知道那是程序的"配置文件"。研究过 .bat 和 .cmd，知道那是"批处理脚本"。每一个文件类型背后，都藏着一小片知识。我就像一只好奇的猫，在系统这个巨大的房间里，东闻闻西嗅嗅，乐此不疲。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">三、批处理：最"朴素"的编程</h3>
  <p>说到批处理，我得好好聊聊。批处理脚本，后缀名是 .bat，是 Windows 自带的一种"程序"。它没什么花哨的语法，就是一行行的命令，写在一个文本文件里，双击就能运行。我一开始觉得它土，后来才发现，它其实特别实用。</p>
  <p>我最开始写的批处理，特别简单，就是一堆"ping"命令，用来测试网络通不通。后来我学会了更多：用"echo"输出文字，用"start"打开程序，用"del"删除文件，用"for"循环……我把它们组合在一起，写出了一个"一键清理垃圾"的脚本——双击它，它就会自动帮我清理临时文件、清空回收站、关闭没用的进程，最后弹出一句"清理完成！"。虽然这个脚本的原理特别简单，但每次我双击它，看着屏幕上的字一行一行地跳出来，我都觉得特别有仪式感。</p>
  <p>我甚至还用批处理，给同学写过一个"恶作剧"脚本——双击之后，屏幕上会一个接一个地弹出窗口，上面写着各种话。当然，都是无伤大雅的小玩笑，我后来也没敢真的发给别人。但写那个脚本的过程，让我明白了：程序不一定要多高级，能解决问题、能带来快乐，就有它的价值。</p>
  <p>批处理让我明白的最重要的一件事是：<em class="k">编程的"入门"，不一定非要装什么高大上的环境，也不一定非要学什么高深的语法</em>。有时候，一个最简单的工具，就能让你体会到"让电脑按你的意思干活"的快乐。而这种快乐，才是让你坚持下去的燃料。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">四、装系统，和"神秘的重装"</h3>
  <p>每个爱折腾电脑的人，早晚都要过"装系统"这一关。我也不例外。</p>
  <p>第一次装系统，起因是那台老电脑卡得实在没法用了。我查了一晚上资料，最后决定：重装系统，从头再来。那时候装系统，不像现在这么简单，要先做启动盘（U盘里放上系统镜像，还得设置电脑从 U 盘启动），过程特别繁琐。我战战兢兢地照着一篇图文教程，一步一步地操作，每一步都像在走钢丝。</p>
  <p>中间还出了个小插曲——我做好启动盘，设置好启动顺序，重启电脑，结果屏幕上出现了一堆英文，然后卡住了，怎么也不进安装界面。我急得满头大汗，以为是启动盘做坏了。后来我冷静下来，仔细看了那行英文，才发现原来是 U 盘没插好，系统没检测到。我重新插紧 U 盘，再试，这次终于进去了。</p>
  <p>装系统的过程，比我想象的久。进度条走走停停，我守在旁边，一步也不敢离开。等终于装完，重新开机，看到那个崭新的系统桌面时，我激动得差点跳起来。那感觉，就像给一台濒临"寿终正寝"的电脑，做了一场大手术，又把它救活了。</p>
  <p>装完系统之后，还有一个重要的工作——装驱动、装软件、配置环境。我那时候才发现，原来"装完系统"不是结束，而是开始。你要装显卡驱动，不然屏幕分辨率不对；要装网卡驱动，不然上不了网；要装各种软件，还要一个个配置好。那一次，我忙了整整一个下午，但也正是那一个下午，让我把"系统"这个抽象的东西，理解得特别具体——原来，电脑从"裸机"到"能用"，中间有这么多环节。</p>
  <p>从那以后，我成了同学眼里的"电脑高手"。谁家电脑坏了，都会来问我。我虽然嘴上说着"我也不太懂"，但心里其实美滋滋的——因为这说明，我那些"不务正业"的探索，是真的有用的。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">五、那些"玄学"问题</h3>
  <p>跟电脑打交道久了，你会发现，有些问题特别"玄学"——你怎么也找不到原因，可它偏偏就是好了；或者，它明明什么问题都没有，可它偏偏就是坏了。</p>
  <p>我遇到过最"玄学"的一个问题，是"重启一下就好了"。那时候我有个程序，运行着运行着，就卡死了，鼠标怎么点都没反应。我气得不行，查了半天，也没找到原因。最后我实在没办法，只能"重启"。结果，重启之后，程序又跑得飞快，跟没事人一样。我盯着屏幕，满脑子问号：刚才到底是哪里出了问题？</p>
  <p>后来我才慢慢明白，这种"玄学"，其实大部分都有科学的解释——可能是内存没释放干净，可能是某个资源被占用了，可能是程序的某个状态没复位。重启之所以"万能"，就是因为它把这些乱七八糟的状态，全都归零重来了。但问题是，你很难在它"发病"的那一瞬间，抓到罪魁祸首。</p>
  <p>还有一次更"玄学"的。我写了一个程序，明明代码看着没问题，可一运行就报错。我反反复复检查了好几遍，愣是找不到哪里错了。就在我快要崩溃的时候，我随手把代码里的一个空格删掉了，再一运行，好了！我整个人都傻了——一个空格，就一个空格，能让程序从报错变成正常？</p>
  <p>我后来才知道，在某些编程语言里，空格、缩进、换行，都是"有意义的"。你多打了一个空格，或者少打了一个缩进，程序的理解就会不一样。这种"差之毫厘，谬以千里"的感觉，让我深刻体会到了编程的"严谨"——在电脑面前，你糊弄不了它，它只认规矩。</p>
  <div class="note reveal">
    <span class="tag">关于"不务正业"</span>
    <p>有人说我整天干些"不务正业"的事。但我想说，我干的这些事，没有一件是白干的。研究注册表，让我更懂系统；折腾批处理，让我更懂命令行；装系统，让我更懂电脑的整体；那些"玄学"问题，让我更懂编程的严谨。它们看着散，其实是一张网，慢慢地，把我这个"程序员"织了起来。</p>
  </div>

</section>

<section class="chapter reveal" id="c12">
  <div class="ch-num">第十二章</div>
  <h2 class="ch-title">低谷：那些想放弃的时刻</h2>

  <p class="ch-lead">前面写了好多"高光时刻"，好像我的编程之路一路顺风顺水似的。但说实话，不是这样的。这一章，我想写写那些最难熬的日子——那些让我怀疑自己、甚至想放弃的时刻。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">一、被一个 bug 卡了三天</h3>
  <p>我印象最深的一次低谷，是被一个 bug 卡了整整三天。</p>
  <p>那是冬天，天冷得厉害。我在写一个程序，功能不复杂，就是有一块逻辑，怎么调都不对。一开始，我以为是自己粗心，改了个小地方就想着好了。结果一运行，还是不对。我又改，还是不对。我再改，还是不对。</p>
  <p>第一天，我改到深夜，越改越烦，最后把鼠标一摔，关了电脑，气呼呼地去睡觉了。第二天放学回家，我心想，今天一定能搞定。结果，又是改到深夜，又是失败。那天晚上，我躺在床上，翻来覆去睡不着，脑子里全是那几行代码。我开始怀疑自己：是不是我太笨了？是不是我根本不适合学编程？</p>
  <p>第三天，我整个人都蔫了。放学回家，我甚至不想打开电脑。我坐在书桌前，看着那台电脑，心里特别矛盾——一方面，我特别想把它解决掉；另一方面，我又害怕打开它，害怕再一次失败。</p>
  <p>最后，我还是打开了电脑。我逼着自己，把那段代码从头到尾，一行一行地"念"给一个不存在的"人"听，假装在给别人讲解。讲到某一行的瞬间，我忽然愣住了——我发现，我把一个条件的逻辑写反了。应该是"如果 A 就做这件事"，我写成了"如果 A 就做另一件事"。就这么一个反过来的判断，让我绕了三天的圈子。</p>
  <p>我改过来，一运行，程序完美地跑通了。那一刻，我没有激动，也没有高兴，我只是长长地舒了一口气，像一块压在心口的石头终于落了地。我靠在椅子上，看着屏幕上的结果，心里只有一句话：总算，熬过来了。</p>
  <p>那三天，是我编程路上最难熬的三天，也是我收获最大的一课。我学会了一件事：<em class="k">当你被一个问题卡住的时候，最有效的办法，不是一直"撞"，而是停下来，换一种方式去看它</em>。就像那句话说的，"当局者迷，旁观者清"。有时候，你离问题太近，反而看不清；你退一步，把它讲给别人听，反而一下子就明白了。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">二、别人在玩，我在写代码</h3>
  <p>我的低谷，不只是技术上的，还有心理上的。</p>
  <p>有一段时间，我特别羡慕我的同学。他们放学回家，写完作业，就能看电视、打游戏、出去玩。而我呢？写完作业，还要坐到电脑前，对着那些看不懂的代码，一坐就是几个小时。有时候，我听到窗外有同学在楼下喊别人出去玩，声音清清楚楚地传进来，而我只能坐在屋里，盯着屏幕上的报错信息发呆。</p>
  <p>那种时候，我会特别怀疑自己：我图什么呢？别人玩得多开心啊，我为什么非要在这里遭这个罪？我也想去玩啊。</p>
  <p>有那么一两次，我真的差点放弃了。我把那个写了一半的程序删掉，关上电脑，打算明天开始，再也不碰代码了。结果呢？第二天放学回家，我又鬼使神差地打开了电脑，又把那个程序重新写了回来。我后来想了想，可能我天生就是这样的人——嘴上说着"不干了不干了"，身体却很诚实。</p>
  <p>但我也慢慢想明白了一个道理：<em class="k">羡慕别人，是没用的；你要想清楚，你自己到底想要什么</em>。我羡慕同学能玩，但他们可能也羡慕我——羡慕我能写出他们看不懂的程序，羡慕我有一件自己真正热爱的事。我既然选择了这条路，就要接受它的代价。别人把时间花在玩上，我把时间花在代码上，这是我们各自的选择，没有谁对谁错，只看你后不后悔。</p>
  <p>我，不后悔。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">三、"学不会"的恐慌</h3>
  <p>还有一种是"学不会"的恐慌。那种感觉，比被 bug 卡住还难受。</p>
  <p>被 bug 卡住，至少说明你在"解决问题"；而"学不会"，是那种你连题目都看不懂的无力感。我学 C++ 的指针、学编译原理的时候，都有过这种感觉——眼前的东西，每一个字都认识，但连在一起，就完全不知道在说什么。</p>
  <p>我记得有一阵子，我特别想搞懂一个概念，翻来覆去地看资料，看一遍不懂，看两遍还是不懂，看三遍……我的脑子像一锅浆糊，越搅越糊。我看着网上那些大神侃侃而谈，说得头头是道，再想想自己，连个基本概念都搞不明白，那种巨大的落差感，压得我喘不过气来。</p>
  <p>那段时间，我甚至不敢再碰那个东西了，一看就头疼。我给自己找借口：算了，这个太难了，我以后再说吧。但"以后"到底是多久以后？我心里其实很清楚，我在逃避。</p>
  <p>后来是怎么走出来的呢？说来也简单——我换了一个角度。我不再逼自己"一下子全懂"，而是把那个大概念，拆成一个个小问题，一个一个地啃。今天只搞懂其中一句是什么意思，明天再搞懂下一句。就像啃一块大骨头，一口啃不动，就一小口一小口地啃。慢慢地，那个曾经让我头大的概念，竟然真的被我啃下了一角。</p>
  <p>这件事让我明白：<em class="k">"学不会"不是因为你笨，而是因为你把它想得太"大"了</em>。任何再难的东西，拆小了，就没有那么可怕了。你不需要一下子学会所有东西，你只需要每天进步一点点。今天比昨天多懂一点，就值得高兴。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">四、低谷教会我的</h3>
  <p>现在回头看那些低谷，我居然有点感激它们。因为它们像磨刀石一样，把我的心性磨得更坚韧了。</p>
  <p>如果没有那三天的煎熬，我不会学会"退一步看问题"；如果没有那次"别人在玩，我在写代码"的怀疑，我不会想清楚自己真正想要什么；如果没有那次"学不会"的恐慌，我不会学会把难题拆小。</p>
  <p>我越来越觉得，编程这条路，其实不只是在学"技术"，更是在练"心"。你面对 bug 的耐心，面对难题的韧性，面对诱惑的定力，这些东西，比任何一行代码都值钱。而它们，都是在那些最难熬的日子里，一点一点磨出来的。</p>
  <p>所以，如果你现在也正被某个问题卡住，或者正怀疑自己适不适合学编程，我想跟你说：别急，也别怕。你不是一个人。所有写代码的人，都走过你正在走的路。那三天的崩溃，我也经历过；那些"学不会"的夜晚，我也熬过。只要你还愿意打开电脑，愿意再试一次，你就还没有输。</p>
  <blockquote>
    编程最难的地方，不是那些看不懂的语法，而是在你一次次失败之后，还能不能有勇气，再点一次"运行"。
    <span class="who">—— 低谷之后，写给自己的话</span>
  </blockquote>

  <h2 class="ch-title">写给身边的人</h2>

  <p class="ch-lead">这篇手记，本来是写给我自己的。但写着写着，我发现我有很多话，想对身边的人说。这些话，当面不好意思讲，就写在这里吧。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">给爸妈</h3>
  <p>爸、妈，这些话，我当面可能说不出口，就在这里跟你们说吧。</p>
  <p>谢谢你们，虽然你们一直觉得我"整天玩电脑"，但从来没有真的没收过我的电脑。你们总说"别把眼睛看坏了""早点睡"，我知道，你们是担心我。我也知道，你们其实不太懂我在电脑上捣鼓的那些东西，但你们还是选择相信我，相信我不是在乱来。这份信任，对我来说特别重要。</p>
  <p>我记得有一次，我拿着一个自己写的小程序，兴冲冲地跑到你们面前，给你们演示。你们其实看得一头雾水，但还是配合地点头说"厉害厉害"。那个画面，我到现在还记得。也许在你们眼里，那不过是一个"小孩玩具"，但对我来说，那是你们第一次"看见"我在做什么。</p>
  <p>我想跟你们说，我不是在玩游戏，我是在学东西。我学的东西，可能现在还看不到什么用处，但它是真的有用的。等我以后真的做出一番成绩来，你们就会明白，你们儿子那几年坐在电脑前敲键盘，不是在浪费时间。</p>
  <p>还有，对不起。我知道我有时候写代码写到半夜，让你们担心了。我以后会注意的，会按时睡觉，会爱护眼睛。你们说的"身体是革命的本钱"，我记在心里了。</p>
  <p>最后，还是想说一句：谢谢你们，愿意让我做我喜欢的事。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">给老师</h3>
  <p>老师，我知道您可能看不到这个网页，但有些话，我还是想写下来。</p>
  <p>谢谢您，信息技术老师。您是第一个，没有把我的爱好当成"不务正业"的老师。您说的那句"好好学，这条路你走得下去"，我记到现在。有时候我写代码写到想放弃的时候，就会想起您这句话，然后告诉自己：再坚持一下。</p>
  <p>我也要跟其他老师道个歉。我知道，我有时候上课走神，脑子里还在想代码的事，这是我不对。我以后会注意的，会把课业放在前面，会尽量不在上课的时候想那些乱七八糟的东西。我会努力平衡好"学生"和"程序员"这两个身份，不会让你们失望的。</p>
  <p>其实我心里一直有个小小的愿望：希望有一天，我能做出一个真正有用的东西，然后骄傲地告诉您：老师，您当年那句话，没有白说。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">给同学</h3>
  <p>同学们，我知道，在你们眼里，我可能是个"怪人"。别人下课在走廊里疯跑，我坐在座位上发呆；别人讨论游戏怎么玩，我念叨着什么"编译""指针""服务器"。你们可能觉得我装，觉得我"不合群"。</p>
  <p>其实我想说，我真不是装的。我不是为了显得自己很厉害，才去学这些东西的。我就是单纯地觉得，它们有意思。就像你们喜欢打球，喜欢听歌，喜欢追剧一样，我喜欢写代码。我们只是喜欢的东西不一样，仅此而已。</p>
  <p>我还记得，有一次你们围着我，看我演示一个我自己写的程序。虽然你们嘴上说着"就这？"，但我看得出来，你们其实挺好奇的。那一刻我心里特别高兴——不是因为我显得多厉害，而是因为，我终于有一件可以"拿得出手"的东西，跟你们分享了。</p>
  <p>所以，如果以后我再说出什么"听不懂的话"，请别觉得我装。你们可以问我，我会尽量用你们能听懂的话，讲给你们听。我也很乐意，带你们看看这个好玩的世界。说不定，你们也会喜欢上它呢。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">给未来的自己</h3>
  <p>最后，写给未来的我自己。</p>
  <p>嗨，几年后的董易龙，你好。我是四年级那个，第一次在电脑上写出"你好，世界"的小孩。</p>
  <p>我不知道你看到这些话的时候，已经走到哪里了。你还记得那个绿色的易语言图标吗？还记得那个让你熬到凌晨的程序吗？还记得你给同学发的第一个 exe 吗？这些事，我写这篇手记的时候，还都记得清清楚楚。</p>
  <p>我希望你已经走得很远了。也许你已经做出了"缔造者"，也许你还在做；也许你已经搞懂了编译原理，也许你还在啃；也许你已经用上了自己写的 IDE，也许那还是个半成品。这些都没关系。我只想提醒你三件事：</p>
  <p>第一，别忘了，你最开始是为什么写代码的。不是因为钱，不是因为名，是因为好奇。如果有一天，你写代码写得麻木了，记得回来看看这篇手记，想想四年级那个盯着屏幕，眼睛发亮的小孩。</p>
  <p>第二，别忘了那些帮助过你的人。那个在网上耐心回答你问题的网友，那个说你"走得下去"的老师，还有一直默默支持你的爸妈。你不是一个人走到今天的。</p>
  <p>第三，别忘了，你答应过自己，要做一个"靠谱"的人。写代码要靠谱，做人也要靠谱。不碰不该碰的东西，守住自己的底线。</p>
  <p>好了，就说这么多。我要回去写代码了。祝你好运，也祝我自己好运。</p>

<section class="chapter reveal" id="c13">
  <div class="ch-num">第十三章</div>
  <h2 class="ch-title">我的工具箱</h2>

  <p class="ch-lead">一个木匠，离不开他的刨子和锯子；一个厨子，离不开他的锅和铲；一个写代码的人，也有自己的一套"家伙什"。这一章，我来晒晒我的工具箱，也聊聊我是怎么用它们的。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">一、编辑器，我的"笔"</h3>
  <p>写代码，第一个要用的工具，就是编辑器——也就是你写代码的那个软件。我用过的编辑器，说多不多，说少不少，一路换过来，也挺有意思。</p>
  <p>最早的时候，我用易语言自带的编辑器。它的界面很"易语言"——窗口、按钮、代码区，都是中文的，看着特别亲切。后来学 C++，用了 Dev-C++，那界面灰扑扑的，但功能该有的都有。再后来学 Python，我一开始居然用系统自带的"记事本"写——你没听错，就是那个最朴素的记事本。我写了一堆代码，存成 .py 文件，再在命令行里运行。现在想想，那真叫一个"原始"。</p>
  <p>用记事本写代码，有个好处，就是让你特别清楚"代码本身"长什么样——没有花里胡哨的颜色，没有自动补全，没有报错提示，就是一排一排的黑字。这让你不得不自己把每一个单词拼对，把每一行都写对。坏处也很明显：太容易出错，而且一旦代码长了，找错误就像大海捞针。</p>
  <p>后来我换上了正经的编辑器，才第一次体会到什么叫"效率"。语法高亮——不同的词显示不同的颜色，一眼就能看出哪里是关键字、哪里是字符串、哪里是注释；自动补全——你打个字母，它就能猜出你想写什么，帮你补全；报错提示——你写错了，它马上用红波浪线标出来，提醒你。这些功能，把我从"记单词""数括号"的苦海里解放了出来，让我能专心去想"逻辑"。</p>
  <p>从记事本到专业编辑器，这个"升级"的过程，让我明白了一个道理：<em class="k">好的工具，不是让你少干活，而是让你把力气花在真正重要的地方</em>。你不需要在"拼写对不对"上浪费精力，才有精力去思考"这个程序该怎么写"。这也是为什么，我后来会痴迷于自己做编辑器——因为我太清楚，一个好的编辑器，对写代码的人来说意味着什么了。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">二、命令行，我的"第二双手"</h3>
  <p>如果说编辑器是我的"笔"，那命令行就是我的"第二双手"。很多人一看到那个黑乎乎的窗口就害怕，但我恰恰相反——我越用越觉得，它才是程序员真正的"主战场"。</p>
  <p>我刚接触命令行，是为了运行 Python。那时候我还不太会装环境，网上教程说，装了 Python 之后，要在命令行里敲"python"，才能运行。我第一次在命令行里敲下"python"，看到那个">>>"的提示符出现的时候，心里还有点小激动——感觉自己像个"黑客"了。</p>
  <p>后来我越来越发现，命令行能干的事，比图形界面多太多了。图形界面，是别人设计好的"按钮"，你只能点它给你摆好的那些；而命令行，是一扇通向系统深处的"大门"，你想干什么，只要敲对命令就行。你想看网络状态？敲"netstat"；你想看进程列表？敲"tasklist"；你想批量改名？写个循环。这些事，在图形界面里要翻好几个菜单才能做到，在命令行里，一行命令就搞定了。</p>
  <p>我还特别喜欢命令行的一点，是它的"确定性"。你在图形界面里点来点去，有时候自己都不知道点到哪了；但在命令行里，你敲了什么，它就执行什么，清清楚楚，明明白白。你甚至可以把你敲过的命令存成一个脚本，下次一键执行——这，就是前面说的"批处理"了。</p>
  <p>我越来越觉得，命令行不是给"大佬"专用的，它是每一个想真正掌控自己电脑的人，都应该学会的"基本功"。它也许不漂亮，不花哨，但它是实实在在的"生产力"。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">三、搜索引擎，我的"老师"</h3>
  <p>要问我编程路上最感谢谁，除了那些带我入门的前辈，我可能要说一句：搜索引擎。</p>
  <p>说实话，我大部分的知识，都是"搜"来的。遇到问题，第一反应不是问人，而是搜。怎么搜，也是一门学问。你不能光输入一个词就回车，你得学会"把问题问清楚"——把报错信息原原本本地贴上去，把问题描述得具体一点，有时候还要加上语言名、软件名。搜出来的结果，也不是全都能用，你得学会"挑"——看发布时间，看回复的人靠不靠谱，看是不是官方文档。</p>
  <p>我还学会了"用英文搜"。很多技术问题，中文搜不到答案，换成英文一搜，答案一大把。一开始我觉得英文搜很麻烦，但慢慢地我也习惯了——因为答案比中文多太多了。这也算是我"被逼着"练英语阅读的一个动力吧。</p>
  <p>用搜索引擎久了，我最大的体会是：<em class="k">搜索引擎不是万能的，但它给了你一个"自己找答案"的能力</em>。这个能力，比任何现成的答案都值钱。因为答案会忘，但"怎么找答案"的方法，一旦学会了，就永远是你的了。</p>
  <p>当然，我也遇到过"搜不到"的时候。那种时候，我就只能自己试、自己想、自己琢磨。虽然辛苦，但往往在这种时候，我学到的东西最多。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">四、浏览器里的"显微镜"</h3>
  <p>除了编辑器、命令行、搜索引擎，我还有一个特别重要的工具——浏览器自带的"开发者工具"。</p>
  <p>你可能见过：在网页上点右键，选择"检查"或者"查看元素"，就会弹出一个窗口，里面全是代码。我第一次发现这个功能的时候，就像发现了新大陆——原来，我可以"拆开"任何一个网页，看它里面到底是怎么写的。</p>
  <p>开发者工具里最常用的，是"元素"面板——你鼠标指到网页的哪个地方，它就能告诉你，这一块是用什么代码画出来的。我学前端的时候，遇到"这个样式是怎么实现的"这种问题，直接打开开发者工具，指上去一看，答案就出来了。这比查任何教程都快。</p>
  <p>还有"控制台"——网页上的程序报错了，错误信息会显示在这里。我以前写网页脚本，一报错就抓瞎，后来学会看控制台，哪里错了、第几行、什么类型，全都清清楚楚。还有一个"网络"面板，能看到网页加载了哪些资源、每个资源花了多长时间、返回了什么数据。我研究网页填表、研究爬虫的时候，最常看的就是它——它能让我"看见"浏览器和服务器之间的每一次"对话"。</p>
  <p>我发现，很多"高手"其实没有什么神秘的工具，他们只是把那些"人人都有"的工具，用到了极致。就像那个浏览器开发者工具，它就在每一个浏览器里，人人都会点开，但很少有人真的去研究它。而一旦你研究明白了，你就像拥有了一台"显微镜"，能看到普通用户永远看不见的世界。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">五、我的"烂笔头"</h3>
  <p>俗话说，好记性不如烂笔头。写代码这件事，尤其需要"烂笔头"。</p>
  <p>我有很多个"小本本"——当然，现在大部分是电子版的。我习惯把自己踩过的坑、解决过的问题、突然想到的点子，随手记下来。记的时候不用想太多，想到什么写什么，像倒豆子一样。等哪天用到的时候，翻一翻，往往能发现不少惊喜。</p>
  <p>我还养成了一个习惯，就是存"代码片段"。有些代码，我写的时候费了好大劲，以后很可能还会用到。我就把它们单独存起来，分门别类放好，下次要用，直接复制，改一改就行。这个习惯，帮我省了不知道多少重复劳动。</p>
  <p>当然，最重要的，还是"备份"。我吃过亏——有一次，我写了一下午的代码，结果电脑突然死机，重启之后，文件打不开了。那一下午的心血，全白费了。从那以后，我养成了随手保存、定期备份的习惯。重要的代码，我甚至会复制好几份，放在不同的地方。虽然麻烦，但总比"一朝回到解放前"强。</p>
  <p>这些习惯，看着不起眼，但它们是支撑我走这么远的"地基"。很多人在编程这条路上半途而废，不是因为他们不够聪明，而是因为他们没养成这些"笨功夫"。而恰恰是这些"笨功夫"，才是最能决定你能走多远的东西。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">六、站在巨人肩膀上</h3>
  <p>最后，我想说说那些"看不见"的工具——前辈们留下的知识和经验。</p>
  <p>我用的每一个编辑器，背后是一群开发者的心血；我敲的每一条命令，是几十年技术积累的结晶；我搜到的每一个答案，是不知道多少人踩过坑之后总结出来的。我就像一个站在巨人肩膀上的小人，用着他们搭建好的梯子，一点点往上爬。</p>
  <p>所以，我一直觉得，学编程的人，应该有一颗"感恩"的心。感恩那些开源软件的开发者，感恩那些在网上无偿分享知识的人，感恩那些写教程、写文档、回答问题的前辈。他们本可以不这么做，但他们做了。而我，正是这些"赠予"的受益者。</p>
  <p>这也是为什么，我后来也学着去网上回答问题、分享经验——因为我也想成为那种"巨人"，哪怕只是很小的一块砖头。我想把我学到的东西，再传下去。这样，后面的人就能站在我肩膀上，看得更远一点。这大概，就是技术圈最动人的地方吧。</p>

    <span class="tag">工具箱小结</span>
    <p>我的工具箱，其实一点也不豪华。一个编辑器，一个命令行，一个搜索引擎，一个浏览器开发者工具，还有一堆记笔记、存代码的习惯。它们每一个，都不值钱；但把它们组合起来，就能支撑起一个完整的"开发者"。工具从来不是越贵越好，够用、会用，才是关键。</p>

  <h2 class="ch-title">代码之外</h2>

  <p class="ch-lead">写了这么多代码的事，你可能以为，我的生活里只有代码了。其实不是的。我也上学、也吃饭、也睡觉，也有自己的小爱好，也有普通小孩都有的烦恼和快乐。这一章，写写代码之外的我。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">一、一个普通学生的普通一天</h3>
  <p>先说说我的一天吧。早上六点半左右，被我妈叫醒，迷迷糊糊地洗漱、吃早饭，然后背着书包去上学。白天就是上课、下课、上课、下课，跟所有学生一样。语文、数学、英语、物理、化学……一科一科地上。中午在学校吃饭，下午接着上课，放学回家。</p>
  <p>到家之后，先写作业。我的作业写得不算快，因为有些题真的要想半天。等作业写完，差不多就晚上了。这时候，才轮到我自己的"时间"——打开电脑，开始我的"第二人生"。</p>
  <p>有人可能会问，你天天这样，不累吗？说实话，有时候累。特别是考试前那段时间，作业多，压力大，回到家真想倒头就睡。但奇怪的是，哪怕再累，只要我打开电脑，开始写代码，我的精神就慢慢回来了。就好像，白天那个我是"上班"的我，晚上这个我，才是"真正的我"。</p>
  <p>我爸妈总说，我写代码的时候，眼睛是发亮的。我自己没注意过，但听他们这么说，我心里还是挺高兴的——说明我是真的喜欢，不是装的。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">二、我的其他爱好</h3>
  <p>除了代码，我其实还有别的爱好。虽然它们没有代码那么"突出"，但它们也是我生活的一部分。</p>
  <p>我喜欢看科幻小说。特别是那种讲人工智能、讲未来世界的，我一看就停不下来。看的时候，我总忍不住想：这个设定，要是用代码实现，该怎么做？这个机器人，它的"大脑"会是什么程序？有时候，一个故事读完，我脑子里已经冒出一堆"如果我来做"的想法了。</p>
  <p>我也喜欢打篮球。虽然打得不好，纯粹是瞎玩，但那种在球场上跑起来、出汗的感觉，特别解压。我跟同学打篮球的时候，谁也不会提代码的事，大家就是痛痛快快地跑、跳、抢、投。那一刻，我就是一个普通的学生，一个普通的少年。</p>
  <p>我还挺喜欢看"科技新闻"的。别人看新闻，看的是明星八卦；我看新闻，看的是哪个公司又发布了什么新产品、哪个技术又有了新突破。我家的电视上，一到科技类的节目，我就会停下遥控器。我爸妈有时候笑我，说我看这些东西能当饭吃吗？我说，不能当饭吃，但能"开眼界"啊。</p>
  <p>这些爱好，看着跟编程没什么关系，但它们其实都在悄悄地"喂养"我对这个世界的好奇心。而好奇心，恰恰是支撑我一直写代码的燃料。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">三、和朋友</h3>
  <p>我的朋友不算多，但都是真朋友。他们大部分不懂代码，但他们都愿意听我讲。</p>
  <p>有一个朋友，我们从小玩到大，关系特别好。他虽然完全不懂编程，但每次我做出什么新东西，他都是第一个"捧场"的人。他会很认真地看我的演示，然后问我"这个能干嘛""那个怎么做的"。他问的问题，有时候幼稚得让我想笑，但他那种真诚的好奇，让我特别感动。我经常想，可能这就是"真正的朋友"吧——他不懂你在干什么，但他懂你。</p>
  <p>还有几个同学，是那种"半懂不懂"的。他们知道我在写代码，偶尔也会来问我"能不能帮我做个什么东西"。比如有人想让我帮他做一个"自动答题"的工具（被我拒绝了，因为那算作弊），有人想让我帮他改一个游戏存档。虽然最后大多没做成，但那些"被需要"的时刻，让我觉得，我的技能是有价值的，是能被人看见的。</p>
  <p>当然，我也交过"塑料朋友"。有些人，平时不找我，一听说我"会写代码"，就凑过来，想让我帮他"免费做个网站""破解个什么东西"。这种时候，我一般都会客气地拒绝。因为我知道，这种人不是真的把你当朋友，他只是想"白嫖"你的技能。真正的朋友，不会这样。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">四、和我的身体</h3>
  <p>写代码的人，最亏待的，可能就是自己的身体了。</p>
  <p>我有一段时间，每天坐在电脑前好几个小时，一坐就是半天，动都不动一下。结果，脖子开始疼，肩膀开始酸，眼睛也经常干涩发红。我妈看到我揉眼睛的样子，心疼得不行，逼着我每隔一段时间就起来活动活动。</p>
  <p>后来我学乖了。我给自己定了个规矩：每写四十分钟，就起来走一走，看看远处，做做眼保健操。虽然有时候写得太投入，会忘掉这个规矩，但大部分时候，我还是会提醒自己：身体是革命的本钱，这话不是开玩笑的。</p>
  <p>我还发现一个"小秘密"：有时候，一个问题想不出来，怎么想都想不通，但只要你站起来，去倒杯水，或者在屋里走两圈，再坐回来，那个答案可能就"啪"地一下蹦出来了。所以，现在每当我卡住的时候，我不再死磕，而是站起来走一走。这大概，就是"磨刀不误砍柴工"吧。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">五、关于"成绩"</h3>
  <p>这一节，我想说说成绩——因为这是我躲不开的话题，也是很多家长最关心的问题。</p>
  <p>我知道，在很多大人眼里，学生嘛，成绩好才是"正道"，写代码那是"不务正业"。我承认，我的成绩不是顶尖的，有时候会偏科，有的科目真的让我很头疼。但我一直在努力，在平衡。我没有因为写代码，就放弃学习；我也没有因为学习，就彻底放下代码。我在试着，让它们"两条腿走路"。</p>
  <p>有人说，你花那么多时间写代码，学习的时间不就少了？我承认，时间是少了。但我总觉得，写代码带给我的东西，是课本上学不到的——它教我怎么思考，怎么解决问题，怎么面对失败。这些东西，也许考试考不到，但它们会跟着我一辈子。</p>
  <p>我也一直在想一个"终极目标"：等我长大了，我想去一个能让我既学知识、又能写代码的地方。我想学计算机，想进一个好的学校，想离我的梦想更近一点。为了实现这个目标，我现在就得努力，把学习搞好，把代码写好。这两件事，不是敌人，是我的左右手。</p>
  <div class="note reveal">
    <span class="tag">关于"生活"</span>
    <p>代码很重要，但它不是我生活的全部。我吃徐州的美食，看我喜欢的书，打我不擅长的篮球，交真心的朋友，陪爱我的家人。代码是照亮我生活的那盏灯，但灯底下，得先有生活，灯才有意义。我不想成为一个只会写代码的机器，我想成为一个——会写代码的、活生生的人。</p>
  </div>

  <h2 class="ch-title">我的"黑历史"</h2>

  <p class="ch-lead">写到现在，我一直都在"树立形象"。但说真的，我这几年，没少干傻事、丢人事。这一章，我主动"自曝"，把我那些黑历史抖搂出来。反正这些事，我不说，总有一天也会被扒出来，还不如自己先交代了。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">一、那些"傻"代码</h3>
  <p>先说说我写过的那些"傻"代码。不是贬低自己，是真的很傻。</p>
  <p>我刚学编程那会儿，写过一段"特别厉害"的代码——有多厉害呢？大概长这样：</p>
  <div class="code-wrap">
    <div class="code-head"><span class="dot r"></span><span class="dot y"></span><span class="dot g"></span><span class="lang">Python · 当年的"神作"</span></div>
<pre><code>if 1 == 1:
    print("对")
if 2 == 2:
    print("对")
if 3 == 3:
    print("对")</code></pre>
  </div>
  <p>你没看错，我当时觉得，能写这么多行代码，特别有成就感。一行一行地写"1==1""2==2""3==3"，写了整整几十行，然后自豪地把它跑起来，看着屏幕上密密麻麻的"对"字，觉得自己是个天才。</p>
  <p>直到后来我才知道，这种东西，用"循环"两个字就能搞定，而且比我那几十行还要"正确"。我还沾沾自喜地把它存了起来，后来有一次翻到，自己都笑了半天。这就是当年的我——一个把"代码行数"当成"厉害程度"的小孩。</p>
  <p>还有一次，我写程序的时候，需要一个"等待"的功能，就是让程序停一会儿再继续。我居然用了最笨的办法——写一个空的循环，让它空转几千次，靠"磨时间"来模拟等待。程序跑起来，CPU 飙到百分百，风扇嗡嗡地转，我还以为是我电脑太卡了。后来我才知道，人家正经的做法，是用"sleep"函数，一行搞定，而且一点都不浪费 CPU。我那个"空转大法"，简直是给电脑上刑。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">二、一次"炫技"翻车</h3>
  <p>下面这件事，是我最想忘、又最忘不掉的一次"翻车"。</p>
  <p>那是一次家庭聚会，亲戚们都在。有个亲戚听说我"会电脑"，就让我"表演一个"。我那时候年轻气盛（其实也不小了，但我确实飘了），一口答应下来，想露一手。</p>
  <p>我打开了命令行，准备输入一个命令，让屏幕上的字变色、闪烁，看起来特别"黑客"。我自信满满地敲下第一行，结果——回车，屏幕上蹦出一行英文：不是正确的命令。我愣住了，赶紧改，又敲了一行，还是不对。亲戚们围在边上，气氛越来越尴尬。我的脸"唰"地一下就红了。</p>
  <p>最后，我实在没办法，只好讪讪地说"今天电脑有点问题"，然后灰溜溜地把命令行关了。后来我才知道，我记错了命令的拼写，少打了一个字母。就一个字母，让我在全家亲戚面前"社死"了一回。</p>
  <p>这件事给我的教训是：<em class="k">没把握的事，别轻易在人前"炫"</em>。你以为你准备充分了，但现实总会给你一记响亮的耳光。从那以后，我再也不"无准备炫技"了——要么我提前试好，要么我就老老实实说"我不会"。总比在众人面前出丑强。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">三、和同学吹的牛</h3>
  <p>还有一次，是在同学面前吹牛，然后被"打脸"。</p>
  <p>那时候我刚学了点网络编程，觉得自己特别了不起。有一天，我跟同学吹牛，说我能"黑进"学校的网站，把它改得面目全非。同学半信半疑地看着我，我那时候也是嘴硬，硬着头皮说"你们等着"。</p>
  <p>回家之后，我打开电脑，准备"大显身手"。结果，我连学校的网站是怎么搭的都不知道，更别说"黑"了。我在网上搜了一堆"教程"，全是些不靠谱的玩意儿，试了半天，一点进展都没有。最后，我不得不承认，我根本做不到。</p>
  <p>第二天到学校，同学问我"黑进去了没"，我支支吾吾地说"那个网站太硬了，攻不破"。同学哈哈一笑，说"我就知道你是吹牛的"。虽然他们是笑着说的，但我当时还是臊得不行。</p>
  <p>这件事让我明白了两件事。第一，吹牛是要付出代价的，吹得越大，打脸越响。第二，也是更重要的——<em class="k">真正的"高手"，从来不会说自己能"黑"什么</em>。真正懂安全的人，恰恰是最守规矩、最谨慎的人。而我那时候的行为，用一个词形容，就是"不懂装懂"，太幼稚了。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">四、那些"低级错误"</h3>
  <p>写代码这几年，我还犯过无数个"低级错误"，多到可以单独写一本书。</p>
  <p>有把"==="写成"="的——结果程序不比较，直接赋值，逻辑全乱套。有把中文字符和英文字符搞混的——中文的全角括号、全角逗号，程序认不出来，报错报得我一脸懵。有忘了在语句后面加分号的——编译直接报错。有把文件名拼错的——明明存了，却死活找不到。有把"新建"当成"另存为"的——写了一个下午的代码，点了一下，全没了。</p>
  <p>最搞笑的一次，是我排错排了整整一个小时，最后发现，问题出在我把两个变量的名字搞混了。一个叫"number"，一个叫"num"，长得太像，我写代码的时候自己把自己绕晕了。我盯着那两行代码，哭笑不得——敢情这半天，是我自己在跟自己较劲。</p>
  <p>这些错误，现在说起来都是笑话，但当时每一个，都让我抓狂过。不过，它们也让我慢慢养成了一些好习惯：写代码的时候，眼睛瞪大一点；看到奇怪的报错，先检查是不是标点符号的问题；保存文件之前，多看一眼文件名。这些"血泪教训"，比任何教材都来得深刻。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">五、为什么我要"自曝"</h3>

  <p>而且，我还想通过这些"黑历史"，告诉那些正在学编程的人：你看，我这么笨，这么爱犯错，不也一路走过来了吗？你犯的那些错，我全都犯过，甚至比你犯得还多。所以，别怕犯错。犯错不可怕，可怕的是因为怕犯错，而不敢开始。</p>

  <h2 class="ch-title">我眼中的未来</h2>

  <p class="ch-lead">写代码的人，大概都喜欢"眺望"——眺望技术的方向，眺望未来的模样。我也不例外。这一章，我想说说，我眼中的未来会是什么样。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">一、关于人工智能</h3>
  <p>要说这几年最火的技术，非人工智能莫属。我能感觉到，世界正在被它一点点改变。</p>
  <p>我记得我第一次接触"人工智能"这个词，是在看一篇新闻报道的时候。报道里说，一个叫 AI 的东西，能自己下棋、自己画画、自己写文章。我当时的第一反应是：真的假的？这不就是科幻小说里才有的东西吗？</p>
  <p>后来，我自己也试着去了解它。我知道了，人工智能背后，其实是一套套复杂的算法和模型——它并不是真的"会思考"，而是通过海量的数据"学习"出规律，然后用这些规律去"预测"。它像一个特别勤奋的学生，看了一百万道题，然后就能回答出类似的题。这么一想，它好像也没那么神秘了。</p>
  <p>但我也不得不承认，AI 的发展速度，快得让人有点害怕。今天它还会"犯蠢"，明天它可能就"无所不能"了。很多人担心，AI 会不会抢了人的饭碗？我自己也在想这个问题。</p>
  <p>我的看法是：AI 会改变很多行业，但它不会"取代"人，只会"淘汰"那些不学习的人。就拿写代码来说，AI 确实能帮我写很多基础的代码，但它写不出我脑子里的"创意"和"想法"。它是个好帮手，但不是我的"替代品"。所以，我一边用着 AI 帮我提效率，一边也在拼命学习那些 AI 替代不了的东西——理解问题的本质，设计解决方案，把控整体的方向。这些，才是人的价值所在。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">二、关于"程序员"这个身份</h3>
  <p>说到未来，我还想聊聊"程序员"这个身份本身。</p>
  <p>在很多人眼里，程序员是一群"格子衫、戴眼镜、头发少"的人，整天跟电脑打交道，闷闷的，不善言辞。我以前也这么觉得。但等我真正走进这个世界，我才发现，这种印象大错特错。</p>
  <p>我见过的程序员，有爱说笑话的，有爱玩音乐的，有爱健身的，有爱写诗的。他们只是恰好会写代码而已。代码是他们的"职业"，但不是他们的"全部"。而且，越是厉害的程序员，往往越不是那种"只会敲键盘"的人——因为他们要跟人沟通，要理解需求，要设计产品，这些，都需要"人的能力"。</p>
  <p>所以，我从来不觉得"程序员"是一个标签。它只是我众多身份中的一个。我是董易龙，我是一个学生，我是一个儿子，我是一个朋友，然后，我是一个会写代码的人。顺序不能反。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">三、我为什么还愿意"从零造轮子"</h3>
  <p>在这个"什么都能搜到、什么都有现成的"时代，很多人觉得，没必要自己造轮子了——能用现成的，为什么要自己写？</p>
  <p>但我的想法，可能有点"不合时宜"。我总觉得，有些东西，你必须亲手做一遍，才能真正懂它。就像学数学，你不能只看别人算，你得自己动手算；就像学游泳，你不能只在岸上看，你得跳进水里扑腾。造轮子，也是一种"学习"——它让你明白，一个东西为什么是这样设计的，它的"底层逻辑"是什么。</p>
  <p>我做的那些项目——编辑器、建站平台、聊天软件、编程语言——如果用现成的工具，可能几个月就能搭个差不多的。但我偏偏选择"从零开始"，一点一点地造。因为我知道，我收获的，不是一个"成果"，而是整个"过程"里的知识和理解。这些东西，是那些现成工具给不了我的。</p>
  <p>当然，我也不是"拒绝一切现成"的固执狂。该用现成的，我也会用。但我用之前，一定会先搞懂它是什么、它怎么工作的。就像我前面说的，<em class="k">先求懂，再求用</em>。这个原则，我打算一直坚持下去。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">四、十年之后的我</h3>
  <p>最后，让我想象一下十年之后的我。</p>
  <p>十年之后，我大概二十好几岁了。那时候，我应该已经离开徐州，去了一个更大的城市，也许上了一所很好的大学，学计算机专业。也许我已经做出了一些真正有用的东西——也许「缔造者」真的成了很多人的工具，也许「汉语言」真的有了第一批用户，也许我的 IDE 真的支持了几十上百种语言。</p>
  <p>但我也知道，这些"也许"，都可能落空。十年之后的我，也许只是一个普通的程序员，每天写着自己觉得无聊的代码，拿着普通的工资。也许我的那些"大梦想"，到最后都没能实现。</p>
  <p>但我想说的是：就算那样，我也不后悔。因为这条路，是我自己选的，我走得很开心。就算最后没能走到"山顶"，这一路上的风景，我也已经看过了，值了。</p>
  <p>况且，谁说得准呢？四年级那个在电脑前偷偷玩4399的小孩，也想不到自己会走到今天。未来的事，谁知道呢。我只知道，我会一直走下去，一直写下去，一直保持那份"好奇心"。剩下的，交给时间吧。</p>
  <blockquote>
    我不知道未来会把我带向哪里。但我知道，只要我还在写代码，我就是在朝着我想去的地方走。
    <span class="who">—— 关于未来，我的答案</span>

  <h2 class="ch-title">有人问过我</h2>

  <p class="ch-lead">自从大家知道我会写代码，就老有人问我各种问题。有的问得特别认真，有的问得让人哭笑不得。这一章，我把那些被问过的问题，挑一些出来，认真回答一遍。说不定，也有你想问的。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">问：你什么时候开始写代码的？</h3>

  <p>所以你看，我开始得并不早，也不是什么"神童"。我就是个普通小孩，只是因为好奇，多往前走了一步。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">问：学编程难吗？</h3>
  <p>说实话，难。但也没你想象的那么难。</p>
  <p>说它难，是因为你要学的东西真的很多，而且很多概念一开始特别抽象，让人抓狂。说它没那么难，是因为现在的学习资源真的太多了——你想学什么，网上都能找到教程，而且大部分都是免费的。你不需要什么高智商，只需要一样东西：耐心。愿意一遍一遍地试，愿意一遍一遍地错，愿意一遍一遍地重来。有这份耐心，编程的大门，迟早为你敞开。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">问：你是怎么坚持下来的？</h3>
  <p>这个问题，很多人问过我。我想了很久，觉得答案就一句话：因为我是真的喜欢。</p>
  <p>很多人以为，坚持做一件事，靠的是毅力、是自律。但我后来发现，靠毅力硬撑，是撑不了太久的。真正能让你一直走下去的，是"喜欢"。你喜欢这件事，你才会在遇到困难的时候，愿意再试一次；你才会在被打击的时候，愿意爬起来继续。所以，如果你想学编程，先别急着问"难不难"，先问问自己："我是不是真的喜欢它？"如果答案是肯定的，那你就已经赢了一大半了。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">问：你写代码有什么"怪癖"吗？</h3>
  <p>哈哈，还真有。我总结了几条，供大家"取笑"：</p>
  <p>第一，我写代码的时候，必须得戴耳机。不一定要听歌，有时候就是听个"环境音"，或者干脆什么都不放，就是戴着。好像耳机一戴，世界就安静了，我就能专心了。</p>
  <p>第二，我特别喜欢在深夜写代码。不是故意熬夜，是觉得夜深人静的时候，思路特别清楚。白天吵吵闹闹的，脑子里乱糟糟的；一到半夜，整个世界都安静下来，脑子里的"代码"就开始顺畅地流淌了。</p>
  <p>第三，我写代码的时候，会不自觉地自言自语。有时候是念叨"这个不对啊"，有时候是突然"哦！我知道了！"。我妈路过我房间，经常看到我一个人对着屏幕嘀嘀咕咕，她觉得我有点"魔怔"了。</p>
  <p>第四，我给变量起名字，特别较真。一个变量的名字，我能纠结半天——既不能太长（敲着累），又不能太短（看不懂），还得见名知意。有一次，为了一个变量叫什么名字，我愣是想了十分钟。你说这算不算怪癖？</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">问：你最喜欢什么语言？</h3>
  <p>这个问题，像一个程序员被问"你最喜欢哪个孩子"一样难答。但我还是试着答一答。</p>
  <p>从感情上说，我最喜欢的是易语言——它是我编程路上的"初恋"，没有它，就没有今天的我。从"好用"上说，我喜欢 Python——它真的让我体会到了"写代码可以这么痛快"。从"敬畏"上说，我最佩服 C++——它让我明白了什么叫"底层"，什么叫"掌控"。</p>
  <p>但如果非要选一个"最喜欢的"，我可能会选 C++。因为它最难，而最难的东西，往往也最有挑战性，最值得征服。虽然我经常被它虐得死去活来，但我还是喜欢它。这大概就是"痛并快乐着"吧。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">问：你未来想做什么？</h3>
  <p>这个问题，我前面已经写过一些了。再简单说一遍吧：我想把我那些"大项目"做完，想学更多更深的计算机知识，想有一天，能做出一件真正有用的、能帮到很多人的东西。</p>
  <p>具体到"职业"，我还没想太清楚。有人说我以后可以当程序员，可以当安全工程师，可以自己创业。我觉得都行，但我更想的，是做一个"能写代码的人"——不管在什么岗位上，只要我能继续写代码，继续做我喜欢的事，我就满足了。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">问：最想对"以前的你"说什么？</h3>
  <p>这个问题，让我想了很久。我有很多话想对四年级那个小孩说，但最想说的，大概是这几句：</p>
  <p>第一句：别怕。以后你会遇到很多看不懂的东西，别怕，慢慢来，你都会学会的。</p>
  <p>第二句：别放弃。会有想放弃的时候，会有觉得"我不行"的时候，但请你再坚持一下，熬过去就好了。</p>
  <p>第三句：谢谢。谢谢你当年那个下午，点开了那个叫"易语言"的东西。谢谢你，没有把它关掉。你的那个"好奇"，改变了我们的一生。</p>

<section class="chapter reveal" id="fanwai2">
  <div class="ch-num">番外二</div>
  <h2 class="ch-title">零碎的话</h2>

  <p class="ch-lead">写到这儿，正文基本就写完了。但还有很多零零碎碎的话，没地方放，又舍不得扔，就都堆在这一章吧。它们不像前面的章节那样有条理，但它们都是我脑子里真实存在过的东西。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">关于命名</h3>
  <p>写代码的人都知道，命名是件大事。一个好的名字，能让别人（包括几天后的你自己）一眼看懂这段代码是干嘛的；一个烂名字，能让整个项目变成一场灾难。</p>
  <p>我早期写代码，特别喜欢用一些"炫酷"的名字——什么"abc""xyz""temp"，觉得这样显得很"高深"。后来我吃够了苦头：一个叫"temp"的变量，我过两天再看，根本想不起来它存的是什么。从那以后，我改了习惯，尽量用"见名知意"的名字。一个变量，宁可名字长一点，也要让人一眼看懂。这个习惯，让我后来回看自己的老代码时，少受了很多罪。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">关于注释</h3>
  <p>注释，就是代码里给人看的说明文字。写代码的人，对注释的态度，可以说是两极分化——有人觉得注释是"美德"，有人觉得注释是"噪音"。</p>
  <p>我自己的态度，是"该写就写，不该写就别写"。什么是"该写"的？就是那些不看注释，根本看不懂的复杂逻辑。我经常遇到这种情况：一段代码，当时写的时候觉得"这谁看不懂啊"，结果过了一个月，再看，一脸懵："这是我写的吗？"这时候我就特别后悔，当初怎么没写注释。</p>
  <p>但也有一种注释，是多余的——比如"这行代码是让 a 等于 1"，这种注释写了等于没写，还占地方。注释的价值，在于解释"为什么"，而不是复述"是什么"。这个道理，我花了挺长时间才想明白。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">关于 bug 和"玄学"</h3>
  <p>前面我写过"玄学"问题，这里再补两句。</p>
  <p>我后来总结出一个规律：大部分"玄学" bug，最后查出来，都不是"玄学"，而是你自己的疏忽。要么是一个拼错的单词，要么是一个搞反的逻辑，要么是一个忘加的判断。电脑不会骗你，它只是诚实地执行你写的话。你觉得它"玄学"，其实是你自己"糊涂"。</p>
  <p>但也有一些 bug，是真的"无解"的——比如，你改了一个无关紧要的地方，然后 bug 就消失了，你根本不知道为什么。这种 bug，我遇到的时候，会先把当前能用的版本备份好，然后继续写。因为我知道，与其跟它死磕，不如先绕过去，说不定哪天就懂了。有时候，问题不是用来"解决"的，而是用来"绕过"的。等你的水平够了，回头看，自然就明白了。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">关于"抄"代码</h3>
  <p>说到学编程，很多人都会问：我能不能"抄"别人的代码？</p>
  <p>我的回答是：能，但要想清楚怎么"抄"。你抄别人的代码，不能是"复制粘贴"就完了——那叫"搬运"，不叫"学习"。你得一行一行地看，看它为什么这么写，想明白它的思路，然后把它"消化"成自己的东西。我学编程的早期，几乎所有的代码都是"抄"来的——但我不是直接复制，而是一行一行地敲，一边敲一边想"这句是什么意思""这句为什么要这么写"。敲完了，我还喜欢自己改一改——换个变量名，加个功能，改个样式。改着改着，我就真的懂了。</p>
  <p>所以，"抄"不是问题，"瞎抄"才是问题。会学习的人，"抄"一遍就学会了；不会学习的人，"抄"一百遍还是不会。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">关于灵感</h3>
  <p>写代码的人，有时候也会聊聊"灵感"。但你千万别以为，写代码的"灵感"，是像写诗一样，坐在那儿等什么"缪斯女神"降临。不是的。</p>
  <p>我的"灵感"，大部分时候，是"憋"出来的。是我盯着一个问题想了半天、查了半天、试了半天，然后某个瞬间，"啪"地一下，脑子里突然冒出一个思路。这个思路，看起来像是"灵光一现"，但其实，它是前面那半天的"苦熬"攒出来的。没有前面的苦熬，就没有后面的"灵光"。</p>
  <p>还有一部分"灵感"，是从"别人的代码"里来的。我逛技术社区，看到别人的一个巧妙写法，会忍不住想：这个思路，能不能用到我的项目里？这个设计，如果我来做，会不会更好？看着看着，点子就冒出来了。所以我说，会"抄"代码的人，从来不缺"灵感"。</p>
  <p>当然，也有那种"洗澡的时候突然想通"的时刻。真的，我在洗澡、走路、吃饭的时候，想通的问题，比坐在电脑前死磕想通的还要多。后来我养成了一个习惯：身上随时揣个东西（或者用手机记），一有念头，就赶紧记下来。因为那些念头，就像肥皂泡，你一个不留神，它就"啪"地破了，再也找不回来。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">深夜的片段</h3>
  <p>最后，我想写一个深夜的片段。那是一个很普通的深夜，我在写代码。</p>
  <p>窗外很安静，偶尔传来远处一两声狗叫。房间里，只有风扇的嗡嗡声和键盘的嗒嗒声。屏幕的光打在我脸上，整个世界仿佛只剩下我和这行代码。</p>
  <p>我盯着屏幕，改了一行，运行，报错；再改，运行，又报错。我有点烦，但又不甘心。我深吸一口气，把视线从屏幕上移开，看向窗外。夜很黑，但远处有几盏灯还亮着。我忽然想：那些亮着灯的窗户里，是不是也有人，正跟我一样，在对着屏幕，改着一行又一行的代码？</p>
  <p>想到这里，我忽然就不觉得孤独了。我回过头，继续改我的代码。这一次，它跑通了。</p>
  <p>屏幕上的结果，在深夜里亮闪闪的，像一颗小小的星星。</p>
  <div class="note reveal">
    <span class="tag">写在最后</span>
    <p>这篇手记，到这里就真的差不多了。它可能不够精彩，可能有点啰嗦，可能有些地方连我自己都觉得写得不太顺，但它是我一笔一笔写出来的，是我这四年，最真实的样子。谢谢你，看到这里。</p>
  </div>

  <div class="ch-num">番外三</div>
  <h2 class="ch-title">徐州，和我</h2>

  <p class="ch-lead">说了这么多代码的事，我也想聊聊我的家乡——徐州。因为不管我以后走到哪里，我的根，都在这里。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">一、一座有故事的城市</h3>
  <p>徐州，在江苏的西北角，是个不大不小的城市。它没有那些大城市那么繁华，但它有一种独特的"厚重感"。老师说，徐州是两汉文化的发源地，是"彭祖故国、刘邦故里、项羽故都"。我小时候听这些，没啥感觉，就觉得是课本上的字。但等我长大了些，再去那些地方走一走，看着那些古老的石头、斑驳的城墙，才慢慢品出一点味道来——原来，我住的地方，藏了这么多故事。</p>
  <p>我记得小时候，爸妈带我去云龙湖玩。那湖很大，水很清，风一吹，湖面上波光粼粼的。湖边有一座山，叫云龙山，不高，但爬上去，能看见整个徐州。我那时候站在山顶，看着下面的房子、马路、汽车，心里就在想：这个城市，好像也挺大的嘛。</p>
  <p>徐州还有一条大运河。那时候我不懂什么叫"运河"，就觉得是一条特别长的河。后来学了历史，才知道这条河在古代有多重要——它是南粮北运的"大动脉"，多少商船货船，就从这条河上，来来往往。我每次路过河边，看着那些依然流淌的水，都会想：几百年前，这里是不是也这么热闹？</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">二、徐州的味道</h3>
  <p>聊家乡，不能不聊吃。徐州的美食，可能没有那些"网红城市"出名，但它们是我记忆里最踏实、最温暖的味道。</p>
  <p>我最爱吃的，是地锅鸡。一个大铁锅，锅里炖着鸡，锅边贴着一圈面饼，饼子一半浸在汤汁里，一半烤得焦脆。夹一块饼，蘸着汤，一口下去，又香又辣又过瘾。每次吃地锅鸡，我都能多吃一碗饭。</p>
  <p>还有把子肉。肥瘦相间的五花肉，炖得软烂入味，配上一碗白米饭，那滋味，简直了。我小时候最爱干的事，就是把把子肉的汤汁浇在米饭上，拌一拌，呼噜呼噜能吃一大碗。</p>
  <p>对了，还有"啥汤"（饣它汤）。那是一种糊状的汤，里面有鸡肉丝、鸡蛋花，还要打一个生鸡蛋进去烫熟。喝的时候，配上一根油条或者一个煎包，那叫一个舒坦。我每次喝啥汤，我妈都说我喝得"稀里哗啦"的，跟小猪一样。</p>
  <p>写代码写到深夜的时候，我常常会饿，一饿，就想起这些吃的。有时候实在馋得不行，就央求我妈明天早上给我买一份啥汤、两根油条。第二天早上，喝上那一口热乎乎的啥汤，就觉得自己又"活过来"了。你看，代码和家乡味，在我这儿，是绑在一起的。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">三、徐州人，和徐州话</h3>
  <p>徐州人，性格里带着一股"实在劲儿"。说话直来直去，不爱拐弯抹角。街上的人，看着都挺"凶"（其实是长得比较"硬朗"），但熟了之后，都特别好相处。我就是在这样的环境里长大的，所以我的性格里，多少也带着点"实在"——不喜欢虚头巴脑的东西，做事喜欢脚踏实地。</p>
  <p>徐州话也挺有意思。比如"管"，意思是"行、可以"；"得劲"，意思是"舒服、痛快"；"不孬"，意思是"不赖、挺好"。我平时在学校说普通话，但一回到家，就自动切换成徐州话。写代码的时候，我脑子里有时候还会冒出徐州话——比如程序跑通了，我会在心里喊一句"得劲！"</p>
  <p>我想，以后我要是真去了外地，听到别人讲普通话，我大概还是会怀念这口徐州话。因为它不光是一种"方言"，更是一种"家的感觉"。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">四、家乡，和我的代码</h3>
  <p>你可能会觉得奇怪：聊家乡，跟写代码有什么关系？</p>
  <p>但我觉得，关系大着呢。因为一个人的"根"在哪，他的"魂"就在哪。我在徐州长大，徐州给了我踏实、质朴的性子，给了我吃不完的家乡味，给了我一群从小玩到大的朋友，给了我一个虽然不富裕、但很温暖的家。这些东西，构成了"我"这个人的底色。</p>
  <p>而我写的那些代码，就是从这个底色里，长出来的花。它们可能不够绚烂，但它们是真实的，是我董易龙写的，是从徐州这片土地上长出来的。</p>
  <p>所以，不管我以后走多远，写多少行代码，我都不会忘了——我是一个徐州娃。</p>
  <div class="note reveal">
    <span class="tag">这一章，写给我的家乡</span>
    <p>徐州不大，但它在我的心里，很大。它装着我所有的童年，所有的第一次，所有"家"的味道。我写代码的手，是在这里长出来的；我这个人，也是在这里长大的。</p>
  </div>

<section class="chapter reveal" id="fanwai4">
  <div class="ch-num">番外四</div>
  <h2 class="ch-title">桌面上的世界</h2>

  <p class="ch-lead">每个人打开电脑，第一个看到的就是"桌面"。桌面这个东西，很能反映一个人的"内在"。有人桌面干净得像新装系统，有人桌面堆满了文件。我的桌面嘛……属于第二种，但又有点不一样。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">一、乱，但有章法</h3>
  <p>我妈每次看到我的电脑桌面，都要吐槽一句："你这桌面，跟猪窝一样！"确实，我的桌面上散落着各种文件——有写了一半的代码，有下载的教程，有随手截的图，有临时存的文档，还有一堆不知道什么时候存的、再也想不起来是什么的东西。</p>
  <p>但我要说句公道话：我的桌面，乱是乱，但乱得有章法。我的所有"正经项目"，都放在 D 盘的一个专门的文件夹里，分门别类，清清楚楚。桌面上的那些"乱"，其实都是"临时区"——是我正在做、还没做完的东西。我做完了，就会把它们收拾进"正经"的地方。</p>
  <p>这就好比我的脑子——表面上看着乱糟糟的，但其实我自己心里有数。哪个项目进行到哪一步了，哪个代码放哪了，哪份资料是重要的，我心里都门儿清。我妈不懂这个，她只看到了"乱"。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">二、我的文件夹们</h3>
  <p>打开 D 盘，你会看到我给自己建的"小王国"。</p>
  <p>有一个文件夹，叫"项目"，里面装着我的那些"大工程"——缔造者、IDE、信鸽、汉语言，每个项目一个子文件夹，里面又分"源码""文档""测试""备份"。虽然我的代码写得可能不怎么样，但我的文件夹分类，绝对是"专业级"的。这大概就是我"实在"的性格在代码世界里的体现——东西可以不好，但规矩必须立好。</p>
  <p>有一个文件夹，叫"资料"，里面全是我从网上存的教程、文档、PDF。什么"C++ 入门到精通""Python 爬虫实战""计算机网络基础"……攒了一大堆，有些我看了，有些我到现在都没打开过。我跟自己说，那是"备用粮"，等哪天需要了再看。至于哪一天……那就不知道了。</p>
  <p>还有一个文件夹，叫"旧物"，里面装着我早期写的那些"黑历史"代码。那个写了五十行"1==1"的 Python 文件，就躺在里面。我时不时会翻一翻，看看当年的自己，然后会心一笑。它提醒着我：你也是从"笨"走过来的。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">三、桌面壁纸</h3>
  <p>说了半天文件，再说说我的桌面壁纸。这虽然是个小事，但也能看出我的"审美"。</p>
  <p>我最喜欢的壁纸，是一张纯黑色的背景，上面只有一行小小的字——"Stay Curious"，保持好奇。每次开机看到它，我都会在心里默念一遍。它像一个小小的"座右铭"，提醒我不要忘了，自己是怎么走到今天的。</p>
  <p>我见过很多人的壁纸，有的是明星，有的是风景，有的是动漫角色。都挺好。但对我来说，还是这行字最合我心意。因为它不是一张"好看的图"，而是一个"提醒"。它告诉我：世界很大，值得好奇。</p>

  <h3 style="font-size:1.15rem;margin:1.8em 0 .6em;color:var(--ink)">四、桌面里的"人生"</h3>
  <p>其实，聊了这么多桌面的事，我想说的是：一个人的桌面，就是他"数字人生"的一个缩影。</p>
  <p>我的桌面上，有乱糟糟的"进行中"，有井井有条的"已完成"，有舍不得扔的"旧物"，还有一句提醒自己的"座右铭"。这就像一个完整的"我"——有点乱，但心里有数；有点怀旧，但一直在往前走；偶尔犯傻，但始终没有忘了方向。</p>
  <p>也许在很多年后，我会换电脑，会换桌面，会把这些文件都搬到新的地方。但我希望，那句"Stay Curious"，会一直留在我的电脑上，也一直留在我心里。</p>
  <div class="note reveal">
    <span class="tag">番外四小结</span>
    <p>这就是我的桌面，我的文件夹，我的小世界。它不精致，但它真实。就像这篇手记，就像我这个人。</p>
  </div>

  <h2 class="ch-title">写完了，但还没写完</h2>
  <p class="ch-lead">这篇手记，从开头的"你好，世界"，写到这里，差不多就告一段落了。写它花了我不少时间，但回头再看，我一点也不后悔——因为它让我重新走了一遍这几年走过的路。</p>
  <p>我发现一个挺有意思的事：当我真的把这些事一件一件写下来的时候，很多我以为忘了的细节，全都自己冒了出来。那个下午的阳光，那台旧电脑嗡嗡响的风扇，那个绿色的易语言图标，那句被我改了又改的"你好，世界"，那个我熬到深夜才跑通的程序……它们像老朋友一样，一个接一个地回来了。</p>
  <p>这条路，我还会继续走下去。也许几年之后，我再回头读这篇手记，会觉得里面的自己很傻、很天真，会脸红。但我不打算删掉它。因为那些"傻"和"天真"，恰恰是当年的我最真实的样子。我想留住它，就像留住一枚褪了色的邮票——它不值钱，但它记载了一段时光。</p>
  <p>谢谢你，愿意花时间，听一个初中生讲完他的故事。</p>
  <p>如果这篇手记，能让屏幕前的你，对编程、对代码、对这个世界多了一点点好奇，那我想，我写它的目的，就达到了。</p>
  <p>我们，在下一个 bug 里见。</p>
  <p>其实，这篇手记写到这里，我本来想就此打住了。但停笔之前，我总觉得还有好多话没说全，像一锅炖了很久的汤，汤都喝完了，锅底还沉着一层料。我想了想，还是把这些"料"，也一并捞出来吧。</p>
  <p>写这篇手记，比我想象的要费劲得多。不是因为没东西写，恰恰相反，是因为东西太多了。这四年，我攒了太多的"第一次"、太多的"踩坑"、太多的"想通了"，真要全部写下来，怕是再写五万字也不够。所以我只能挑挑拣拣，把那些最能代表我的、最有味道的，留在了纸上。很多没写进去的事，不是它们不重要，而是它们太琐碎，琐碎到只适合活在记忆里，不适合写在网页上。</p>
  <p>写的过程里，我还发现了一件有意思的事：每当我想起一件旧事，就会像打开了一个抽屉，连带着拽出一串相关的事。比如我想起易语言，就想起了那个绿色的图标，想起了第一次编译成功的那个下午，想起了精易模块，想起了那些让我头大的报错……这些记忆，像一串糖葫芦，一串一串地往外冒。有些记忆，我本以为早就忘了，没想到它们一直在那儿，只是等着我去"打开"。</p>
  <p>我也想借这个机会，认真地说几句"谢谢"。</p>
  <p>谢谢易语言。虽然现在它已经渐渐淡出了很多人的视野，虽然它有这样那样的局限，但在我最需要"入门"的时候，是它给了我一个温柔的台阶，让我没有在第一道坎上摔倒。它是我编程路上的第一位老师，我永远敬它。</p>
  <p>谢谢 Python 和 C++。它们一个教会我"快"，一个教会我"深"。如果没有它们，我可能永远只会"玩"电脑，而不会真正"懂"电脑。</p>
  <p>谢谢互联网上那些素不相识的前辈。你们写的教程、答的问题、分享的经验，是我最好的"老师"。我们可能永远不会见面，但你们在我心里，早就成了一个个温暖的名字。</p>
  <p>谢谢我的家人，我的老师，我的朋友。谢谢你们的理解、支持和陪伴。没有你们，我走不到今天。</p>
  <p>最后，谢谢正在看这篇手记的你。谢谢你，愿意花时间，听一个初中生讲了这么久的"流水账"。如果你能从里面读到一点点"好奇"和"勇气"，那我这篇手记，就没有白写。</p>
  <p>至于这篇手记本身——我想说，它不完美。它可能有点啰嗦，有点跳跃，有些地方写得不够好。但它是真诚的，每一个字都是。我不打算再"美化"它了，因为它已经是我最真实的样子了。</p>
